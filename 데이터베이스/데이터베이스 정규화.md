## 데이터베이스 정규화 (Database Normalization)

**정규화란?**
- 관계형 데이터베이스의 설계에서 중복을 최소화하게 데이터를 구조화하는 프로세스
- 데이터의 **무결성(Integrity)** 을 유지하고, 저장 용량을 줄이며, **이상(Anomaly) 현상**을 방지하는 것이 목적

**이상(Anomaly) 현상의 종류**
1. **삽입 이상 (Insertion Anomaly):** 데이터를 저장할 때 불필요한 정보까지 함께 저장해야만 하는 현상.
2. **갱신 이상 (Update Anomaly):** 중복된 데이터 중 일부만 수정되어 데이터의 불일치가 발생하는 현상.
3. **삭제 이상 (Deletion Anomaly):** 어떤 정보를 삭제할 때, 유지되어야 할 유용한 정보까지 함께 삭제되는 현상.

### 정규화 단계 및 예시

**1. 제1 정규화 (1NF)**
- **정의:** 테이블의 모든 컬럼이 **원자값(Atomic Value)** 을 가져야 함. 즉, 하나의 컬럼에 여러 개의 값이 들어가거나 반복되는 그룹이 있으면 안 됨
- **예시:**
    - *Before (위반):* `취미` 컬럼에 "축구, 농구"와 같이 여러 값이 들어감.
    - *After (준수):* `취미`를 별도의 행으로 나누거나, 별도의 테이블로 분리하여 각 행이 하나의 취미만 가지도록 함.

**2. 제2 정규화 (2NF)**
- **정의:** 1NF를 만족하면서, **부분 함수 종속(Partial Functional Dependency)을 제거**해야 함
    - 기본키가 복합키(두 개 이상의 컬럼으로 구성)일 때, 기본키의 일부 컬럼에만 종속되는 속성이 없어야 함. (완전 함수 종속 충족)
- **예시:**
    - *Before (위반):* 기본키가 `(학생번호, 수강과목)`인 테이블에 `학생이름` 컬럼이 존재. `학생이름`은 `수강과목`과는 관계없이 `학생번호`에만 종속됨.
    - *After (준수):* `(학생번호, 학생이름)` 테이블과 `(학생번호, 수강과목, 성적)` 테이블로 분리.

**3. 제3 정규화 (3NF)**
- **정의:** 2NF를 만족하면서, **이행적 함수 종속(Transitive Functional Dependency)을 제거**해야 함.
    - 기본키가 아닌 속성들 간의 종속성을 제거 (A → B, B → C 일 때 A → C가 성립하는 관계)
- **예시:**
    - *Before (위반):* `학생번호` → `학과이름`, `학과이름` → `학과위치`. `학생번호`를 알면 `학과위치`를 알 수 있는 이행적 종속 존재.
    - *After (준수):* `(학생번호, 학과이름)` 테이블과 `(학과이름, 학과위치)` 테이블로 분리.

**4. BCNF (Boyce-Codd Normal Form)**
- **정의:** 3NF를 만족하면서, **모든 결정자가 후보키(Candidate Key) 집합에 속해야** 함
    - 후보키가 아닌 속성이 기본키의 일부를 결정하는 경우를 제거. 강한 제3 정규화라고도 함
- **예시:**
    - *상황:* `(학생번호, 과목명)`이 기본키. 교수는 하나의 과목만 담당(`교수명` → `과목명`).
    - *Before (위반):* 테이블에 `(학생번호, 과목명, 교수명)`이 있음. `교수명`은 `과목명`을 결정하지만, 후보키가 아님.
    - *After (준수):* `(학생번호, 교수명)` 테이블과 `(교수명, 과목명)` 테이블로 분리.

### 역정규화 (Denormalization)

**정의**
- 정규화된 데이터베이스의 성능(주로 읽기 성능)을 향상시키기 위해 의도적으로 중복을 허용하거나 테이블을 합치는 과정

**사용 이유**
- 지나친 정규화로 인해 조인(Join) 연산이 너무 많아져 조회 성능이 저하될 때 사용
- 통계 정보나 요약 정보를 미리 계산하여 별도 컬럼에 저장함으로써 실시간 연산 부하를 줄일 때 사용 (예: 게시글의 '좋아요 수', '댓글 수')

**주의사항**
- 데이터 중복으로 인해 데이터 무결성이 깨질 위험이 있음
- 데이터 갱신(Insert, Update, Delete) 시 중복된 데이터들을 모두 동기화해주는 추가적인 로직이 필요
