# 행 기반 vs 열 기반 데이터베이스

데이터베이스를 선택할 때, 서비스의 목적에 따라 행 기반 DB를 쓸지, 열 기반 DB를 쓸지 결정하는 것은 매우 중요함

두 방식의 차이는 데이터를 디스크에 **물리적으로 어떻게 저장하는지**에 있음

---

## 1. 행 기반 데이터베이스 (Row-oriented)

**저장 방식**: 한 줄(Row)의 모든 데이터를 묶어서 저장함
`[1, '김철수', 30, '서울'] [2, '이영희', 25, '부산'] ...`

**핵심 특징**: "한 줄의 모든 데이터를 한 번에 읽고 쓴다"

### 최적화된 작업: OLTP (Online Transaction Processing)
*   `INSERT`, `UPDATE`, `DELETE` 등 **단일 레코드**에 대한 작업이 빈번한 환경에 적합함
*   `SELECT * FROM users WHERE id = 123;` 처럼 특정 한 건의 모든 정보가 필요할 때 유리함

### 실무 예시: "온라인 쇼핑몰 백엔드"
*   **주문 상세 조회**: 특정 주문 번호(ID)에 해당하는 모든 정보(주문자, 상품, 금액, 주소 등)를 한 번에 가져와야 함
*   **회원 정보 수정**: 특정 회원의 주소나 비밀번호를 변경함
*   **게시글 작성**: 하나의 게시글(row)을 통째로 `INSERT` 함

이처럼 행 기반 DB는 한 건의 레코드에 대한 모든 컬럼이 필요할 때, 디스크에서 한 번의 I/O로 모든 데이터를 가져올 수 있어 매우 효율적

*   **대표 DB**: **MySQL, PostgreSQL, Oracle, MS-SQL** 등 우리가 흔히 사용하는 대부분의 관계형 데이터베이스(RDB)

---

## 2. 열 기반 데이터베이스 (Column-oriented)

**저장 방식**: 열(Column) 단위로 데이터를 묶어서 저장함
`[1, 2, ...] ['김철수', '이영희', ...] [30, 25, ...] ['서울', '부산', ...]`

**핵심 특징**: "필요한 열의 데이터만 골라서 읽는다"

### 최적화된 작업: OLAP (Online Analytical Processing)
*   수억 건의 데이터에서 특정 몇 개 컬럼만 사용하여 **집계 및 통계**를 내는 작업에 최적화되어 있음
*   `SELECT AVG(age) FROM users;` 처럼 대량의 데이터에서 특정 컬럼만 읽을 때 유리함

### 실무 예시: "데이터 분석 플랫폼 (Data Warehouse)"
*   **월별 매출 통계**: 10억 건의 판매 기록에서 `판매일`과 `판매금액` 컬럼만 읽어서 월별 합계를 계산함 (다른 컬럼인 `구매자ID`, `상품명` 등은 전혀 읽지 않으므로 I/O가 획기적으로 줄어듬)
*   **사용자 행동 분석**: 특정 기간 동안 사용자들이 클릭한 버튼(`event_type`)의 분포를 계산함

열 기반 DB는 같은 타입의 데이터가 연속으로 저장되어 **압축 효율이 매우 높고**, 분석에 필요한 컬럼만 읽기 때문에 압도적인 성능을 보임

*   **대표 DB**: **Google BigQuery, Amazon Redshift, ClickHouse, Snowflake**

---

## 3. 비교 요약

| 구분 | **행 기반 (Row-oriented)** | **열 기반 (Column-oriented)** |
| :--- | :--- | :--- |
| **저장 단위** | 행 (Row) | 열 (Column) |
| **주요 사용처** | **OLTP** (온라인 서비스) | **OLAP** (데이터 분석, 통계) |
| **유리한 쿼리** | `SELECT * FROM ... WHERE id = ?` | `SELECT col, SUM(col2) FROM ... GROUP BY col` |
| **읽기 패턴** | 한 번에 한 줄 전체를 읽음 | 필요한 열만 골라서 읽음 |
| **쓰기 패턴** | 단일 행 `INSERT/UPDATE`에 유리 | 대량의 데이터를 한 번에 `INSERT` 하는 데 유리 |
| **압축률** | 낮음 | **높음** (같은 타입 데이터가 모여있음) |
| **대표 제품** | MySQL, PostgreSQL, Oracle | BigQuery, Redshift, ClickHouse |
