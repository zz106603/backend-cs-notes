# NoSQL 데이터베이스 유형

NoSQL(Not Only SQL)은 관계형 데이터베이스(RDB)와 다른 방식으로 데이터를 저장하고 관리하는 데이터베이스 시스템을 총칭

서비스의 목적과 데이터의 특성에 따라 적합한 유형을 선택하는 것이 중요함

---

## 1. Key-Value Store (키-값 저장소)

*   **데이터 모델**: 가장 단순한 형태로, 고유한 `Key`에 하나의 `Value`를 저장함 (마치 Java의 `HashMap`처럼)
*   **핵심 특징**: 구조가 단순하여 읽기/쓰기 속도가 매우 빠름
*   **대표 DB**: **Redis**, Memcached, Amazon DynamoDB

### 실무 예시
1.  **세션 캐싱 (Session Caching)**: 사용자의 로그인 세션 정보(Value)를 세션 ID(Key)로 저장함. 사용자가 요청할 때마다 DB를 조회하는 대신, 메모리 기반의 Redis에서 빠르게 세션 정보를 가져와 응답 속도를 높임
2.  **실시간 순위표 (Leaderboard)**: 게임 점수(Value)를 사용자 ID(Key)로 저장하고, Redis의 Sorted Set 같은 자료구조를 활용하여 실시간으로 랭킹을 집계함

---

## 2. Document Store (문서 저장소)

*   **데이터 모델**: 데이터를 유연한 구조의 **JSON/BSON**과 같은 문서(Document) 형태로 저장함
*   **핵심 특징**: 스키마가 정해져 있지 않아, 같은 컬렉션 안에서도 문서마다 다른 필드를 가질 수 있음. 개발자가 객체를 다루듯 직관적으로 사용할 수 있음
*   **대표 DB**: **MongoDB**, Couchbase

### 실무 예시
1.  **온라인 쇼핑몰 상품 카탈로그**: `상품`이라는 하나의 문서에 상품명, 가격, 사이즈, 색상 등 모든 정보를 담음. "책" 상품은 `저자`, `ISBN` 필드를, "의류" 상품은 `사이즈`, `재질` 필드를 갖는 등 상품 종류에 따라 유연하게 구조를 가져갈 수 있음
2.  **블로그 게시물 관리**: `게시물` 문서 안에 제목, 내용, 작성자, 태그 배열, 댓글 객체 배열 등을 모두 포함하여 관련 데이터를 한 번에 읽고 쓸 수 있음

---

## 3. Column-Family Store (컬럼 패밀리 저장소)

*   **데이터 모델**: 행(Row)이 아닌 열(Column) 단위로 데이터를 저장함. 여러 열을 묶어 "컬럼 패밀리"라는 단위로 관리함
*   **핵심 특징**: 특정 열만 읽는 분석 쿼리에 매우 효율적이며, 대규모 쓰기 작업에 최적화되어 있음
*   **대표 DB**: **Apache Cassandra**, HBase, Google Cloud Bigtable

### 실무 예시
1.  **IoT 센서 데이터 수집**: 수백만 개의 센서로부터 초당 수집되는 시계열 데이터(온도, 습도 등)를 저장함. "지난 1시간 동안의 모든 센서의 온도 값"을 조회할 때, `온도` 컬럼만 읽으면 되므로 I/O가 획기적으로 줄어듬
2.  **메시징 서비스**: 사용자의 채팅 메시지를 저장할 때, 쓰기 성능이 매우 중요함. Cassandra는 높은 쓰기 처리량을 제공하여 대규모 메시지를 지연 없이 저장할 수 있음

---

## 4. Graph Store (그래프 저장소)

*   **데이터 모델**: 데이터를 **노드(Node, 정점)** 와 그 사이의 **관계(Edge, 간선)** 로 표현함
*   **핵심 특징**: 데이터 간의 복잡한 관계를 탐색하고 질의하는 데 특화되어 있음. RDB의 `JOIN`을 수십 번 해야 할 쿼리를 매우 빠르게 처리함
*   **대표 DB**: **Neo4j**, Amazon Neptune

### 실무 예시
1.  **소셜 네트워크**: "내 친구의 친구"를 찾는 쿼리는 그래프 탐색을 통해 매우 간단하고 빠르게 수행할 수 있음
2.  **추천 엔진**: "이 상품을 구매한 다른 사람들이 함께 구매한 상품"이나 "나와 비슷한 취향을 가진 사용자가 좋아하는 영화" 등을 추천할 때, 사용자와 상품 간의 관계를 분석하여 결과를 도출함

---

## 5. 요약 비교

| 구분 | **Key-Value** | **Document** | **Column-Family** | **Graph** |
| :--- | :--- | :--- | :--- | :--- |
| **데이터 모델** | `Key: Value` | JSON/BSON 문서 | 열(Column) 묶음 | 노드와 관계 |
| **스키마** | 없음 | **유연함** | 유연함 | 유연함 |
| **주요 장점** | **매우 빠른 속도** | 유연성, 개발 편의성 | **대규모 쓰기/분석** | **관계 탐색** |
| **주요 사용처** | 캐싱, 실시간 순위표 | 콘텐츠 관리, 상품 정보 | 시계열 데이터, 로깅 | 소셜 네트워크, 추천 엔진 |
| **대표 제품** | Redis | MongoDB | Cassandra | Neo4j |
