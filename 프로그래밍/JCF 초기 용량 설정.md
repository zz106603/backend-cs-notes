### JCF 초기 용량 설정의 중요성 (Load Factor & Threshold)

**1. JCF (Java Collections Framework)란?**
- 자바에서 데이터를 저장하는 자료구조(List, Set, Map 등)와 이를 처리하는 알고리즘을 구조화하여 제공하는 프레임워크
- **대표적인 구현체:** `ArrayList`, `HashMap`, `HashSet`, `LinkedList` 등
- 개발자가 직접 자료구조를 구현하지 않고, 표준화된 방식을 통해 효율적으로 데이터를 관리할 수 있게 해줌

---

### 2. 왜 초기 용량(Initial Capacity)을 설정해야 하나요?

JCF의 대부분(특히 `ArrayList`, `HashMap`)은 내부적으로 **배열(Array)** 을 사용하여 데이터를 저장함. 하지만 배열은 한 번 생성하면 크기를 바꿀 수 없음

**문제점: 리사이징(Resizing) 오버헤드**
1.  데이터가 꽉 차면, 기존 배열보다 더 큰(보통 1.5배~2배) 새로운 배열을 생성함
2.  기존 배열에 있던 **모든 데이터를 새로운 배열로 복사**함 (`System.arraycopy`)
3.  `HashMap`의 경우, 배열 크기가 바뀌면 해시값도 다시 계산해서 넣어야 하는 **재해싱(Re-hashing)** 과정이 일어남 (매우 비싼 연산)
4.  이 과정에서 불필요한 객체 생성과 GC(Garbage Collection)가 발생하여 성능이 저하됨

**해결책**
- 저장할 데이터의 개수를 대략적으로 알고 있다면, **생성할 때 미리 용량을 지정**하여 리사이징이 발생하지 않도록 함

---

### 3. 핵심 개념: 로드 팩터와 임계점 (HashMap 기준)

`HashMap`이나 `HashSet`은 언제 배열을 늘릴지 결정하기 위해 두 가지 변수를 사용함

**1. 용량 (Capacity)**
- 현재 저장소(버킷 배열)의 크기
- 기본값(Default): **16**

**2. 로드 팩터 (Load Factor, 적재율)**
- "통이 얼마나 찼을 때 크기를 늘릴 것인가?"에 대한 비율
- 기본값(Default): **0.75 (75%)**
- 0.75란 의미는, 통의 75%가 차면 2배로 확장하겠다는 뜻
    - 값이 1.0에 가까울수록: 메모리를 아끼지만, 해시 충돌 가능성이 높아져 검색 속도가 느려질 수 있음
    - 값이 0.5에 가까울수록: 검색 속도는 빠르지만, 메모리 낭비가 심해짐

**3. 임계점 (Threshold)**
- 실제로 리사이징이 발생하는 데이터 개수
- **공식:** `Threshold = Capacity * Load Factor`
- 예: 용량이 16이고 로드 팩터가 0.75라면, `16 * 0.75 = 12`. 즉, 데이터가 **12개를 넘어가면(13개째)** 용량이 32로 늘어남

---

### 4. 실무 예시: 올바른 초기 용량 계산법

**상황**
- `HashMap`에 데이터를 **100개** 저장하려고 함

**나쁜 예 (기본 생성자 사용)**
```java
Map<String, Integer> map = new HashMap<>(); // 용량 16, 임계점 12
```
- 13개 넣을 때 -> 32로 확장 (재해싱)
- 25개 넣을 때 -> 64로 확장 (재해싱)
- 49개 넣을 때 -> 128로 확장 (재해싱)
- **결과:** 데이터를 다 넣기도 전에 **3번이나 리사이징**이 발생함

**좋은 예 (계산된 용량 설정)**
- 공식: `필요한 개수 / 로드 팩터 + 1.0`
- 계산: `100 / 0.75 + 1 = 134.33...` -> 약 **135** 이상으로 설정
- (참고: HashMap은 내부적으로 2의 거듭제곱으로 용량을 맞추므로, 135를 넣으면 자동으로 256으로 잡힘)

```java
// 100개를 담아도 리사이징이 절대 발생하지 않음
Map<String, Integer> map = new HashMap<>(135); 
```

**ArrayList의 경우**
- 로드 팩터 개념이 없고, 꽉 차면 늘어남. 그냥 개수만큼 잡아주면 됨
```java
List<String> list = new ArrayList<>(100);
```

### 요약

1.  **JCF**는 편리하지만, 내부적으로 배열을 쓰기 때문에 크기 변경 시 **복사 비용(Resizing)** 이 듬
2.  **HashMap**은 `Capacity * Load Factor(0.75)`인 **임계점(Threshold)** 을 넘으면 크기를 2배로 늘리고 **재해싱**함
3.  데이터 개수를 예측할 수 있다면, **`개수 / 0.75`** 정도로 초기 용량을 설정하여 성능을 최적화
