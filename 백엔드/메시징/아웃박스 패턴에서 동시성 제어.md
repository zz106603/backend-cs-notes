# Outbox Pattern에서 동시성 제어: Unique Constraint vs Pessimistic Lock

Outbox Pattern에서 반드시 해결해야 하는 동시성 문제는 크게 두 가지

1. **동일 이벤트가 중복 저장되는 문제 (Create Race)**
2. **여러 Poller가 동일 메시지를 동시에 처리하는 문제 (Ownership Race)**

문제 성격이 다르기 때문에 해결 방식도 달라짐

---

## 1. Create Race: Unique Constraint + UPSERT

동일한 이벤트가 동시에 들어오면 같은 Outbox Message가 중복 저장될 수 있음

```text
Request A → insert
Request B → insert
```

예를 들어 같은 `idempotency_key`를 가진 요청이 동시에 처리되면 중복 row가 생성될 위험이 있음

이를 방지하기 위해 `idempotency_key`에 Unique Constraint를 두고, PostgreSQL의 UPSERT를 사용했음

```sql
INSERT INTO outbox_message (...)
VALUES (...)
ON CONFLICT (idempotency_key)
DO UPDATE ...
RETURNING *
```

동작 방식은 다음과 같음

* 최초 요청 → INSERT
* 동일 요청 재시도 → CONFLICT 발생 → UPDATE
* 다른 payload → 충돌로 판단

추가로 `payload_hash`를 비교해 **같은 key라도 payload가 다르면 중복 요청으로 인정하지 않도록** 했음

### 왜 락을 사용하지 않았는가?

이 문제는 **기존 row 수정이 아니라 새 row 생성 경쟁**임

* 비관적 락 (`FOR UPDATE`) → 잠글 row가 아직 없음
* 낙관적 락 (`version`) → 기존 row가 있어야 함

즉 Create Race는 락보다 **DB Unique Constraint가 가장 적합**함

---

## 2. Ownership Race: FOR UPDATE SKIP LOCKED

Outbox Poller는 저장된 `PENDING` 메시지를 가져와 publish함

문제는 여러 Poller가 동시에 같은 row를 가져갈 수 있다는 점

```text
Poller A → row 101 선택
Poller B → row 101 선택
```

이 경우 동일 메시지가 중복 publish될 수 있음

이를 막기 위해 Poller는 `FOR UPDATE SKIP LOCKED`를 사용

```sql
SELECT id
FROM outbox_message
WHERE status = 'PENDING'
FOR UPDATE SKIP LOCKED
```

의미:

* **FOR UPDATE** → 선택한 row를 즉시 lock
* **SKIP LOCKED** → 이미 lock된 row는 건너뜀

예:

```text
Poller A → row 101 lock
Poller B → row 101 skip → row 102 처리
```

이렇게 여러 worker가 충돌 없이 작업을 분배할 수 있음

또한 row 선택과 상태 변경을 하나의 SQL로 묶어 race condition도 방지했음

```sql
WITH picked AS (...)
UPDATE ...
RETURNING *
```

---

# 정리

Outbox Pattern에서 동시성 제어 방식은 문제 유형에 따라 선택해야 함

| 문제             | 해결 방식                      | 이유           |
| -------------- | -------------------------- | ------------ |
| Create Race    | Unique Constraint + UPSERT | 새 row 생성 경쟁  |
| Ownership Race | FOR UPDATE SKIP LOCKED     | 기존 row 처리 경쟁 |

핵심 기준은 다음과 같음

```text
Create Race → Unique Constraint
Update / Ownership Race → Lock
```

즉 Outbox Pattern에서는
**저장 단계에서는 중복 생성 방지**,
**처리 단계에서는 중복 처리 방지**가 핵심
