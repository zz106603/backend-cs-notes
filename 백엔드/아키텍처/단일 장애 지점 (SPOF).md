## 단일 장애 지점(SPOF)
- Single Point Of Failure, SOPF
- 전체 시스템에서 제대로 동작하지 않는 경우, 전체 시스템이 중단되는 특정 구성 요소를 의미
- 가용성 (Availability)
  - 정상적인 사용 시간(Uptime)을 전체 사용 시간(Uptime + Downtime)으로 나누어 구할 수 있음
  - 가용성이 99.999% 처럼 높은 경우에 고가용성(High Availability, HA)라고 함
  - 시스템이 고가용성을 만족하기 위해서는 SPOF를 식별하고 개선하는 작업이 필요

---

### SOPF를 식별하고 개선
```text
1. API Server 1대를 운용합니다.
2. DB는 Master Replica 구성을 사용합니다.
3. Master DB는 1대이며, 3대의 Replica DB를 사용하고 있습니다. (Failover는 지원합니다.)
```

- 현재 서버는 단일 서버로 구성되어 있음
  - OOM (Out Of Memory)
  - 네트워크 장애
  - 자원 고갈
  - 하드웨어 장애
  - 서버의 고장이 전체 시스템의 고장으로 이어질 수 있음
- 서버를 이중화하고, 로드 밸런서를 사용할 수 있음
- 이중화
  - 동일한 애플리케이션을 여러 서버에 배포하여 한 서버가 다운되더라도 다른 서버가 서비스를 제공할 수 있도록 함
- 로드 밸런서
  - 서버에 들어오는 트래픽을 여러 서버로 분산
  - 특정 서버가 고장나는 경우, 로드 밸런서에서 해당 서버로 향하는 요청을 다른 정상 서버로 전달

---

### 서버를 이중화할 때 점검 사항

서버 이중화 시 고려해야 할 대표적인 사항들은 다음과 같습니다.

#### 1. 동시성 문제 (Concurrency)
- **문제점**: 단일 서버에서 사용하던 `synchronized`, `ReentrantLock` 등의 동기화 메커니즘은 다중 서버 환경에서 작동하지 않음
- **해결 방안**: 분산 락(Distributed Lock)이나 데이터베이스 락(DB Lock)을 사용하여 데이터 일관성을 보장해야 함

#### 2. 세션 불일치 (Session Inconsistency)
- **문제점**: 세션 기반 인증 사용 시, 사용자의 요청이 서로 다른 서버로 전달되면 세션 정보가 없어 로그인이 풀리는 등의 문제 발생
- **해결 방안**:
  - **Sticky Session**: 특정 사용자의 요청을 항상 동일한 서버로 전달
  - **Session Clustering**: 여러 서버 간 세션 정보를 동기화
  - **외부 세션 저장소**: Redis, Memcached 등을 사용하여 세션을 별도로 관리
  - **토큰 기반 인증**: JWT 등을 사용하여 서버가 상태를 저장하지 않도록 변경(Stateless)

#### 3. 로그 및 메트릭 통합 관리
- **문제점**: 로그와 메트릭이 각 서버에 분산되어 저장되므로 전체적인 시스템 상태 파악이 어려움
- **해결 방안**: ELK Stack(Elasticsearch, Logstash, Kibana)이나 Prometheus/Grafana 등을 도입하여 로그와 메트릭을 중앙에서 수집하고 시각화해야 함

#### 4. 로드 밸런싱 알고리즘 (Load Balancing)
- **중요성**: 트래픽을 효율적으로 분산하지 못하면 특정 서버에 부하가 집중되어 이중화의 효과가 감소함
- **고려 사항**: Round Robin, Least Connection, IP Hash 등 서비스 특성에 맞는 적절한 알고리즘 선택 필요

#### 5. 배포 전략 (Deployment)
- **문제점**: 서버 수가 늘어날수록 배포 시간이 증가하고, 버전 불일치 문제가 발생할 수 있음
- **해결 방안**:
  - 무중단 배포 전략(Blue-Green, Rolling, Canary) 수립
  - CI/CD 파이프라인을 통한 자동화된 배포 및 롤백 프로세스 구축
