# 클라우드 서비스 모델 (IaaS, PaaS, SaaS)

클라우드 컴퓨팅 서비스는 제공하는 범위와 관리 책임에 따라 크게 세 가지 모델로 나뉨

백엔드 개발자는 이 모델들을 이해하고 서비스의 요구사항에 맞춰 적절한 것을 선택하는 것이 중요함

---

## 1. 클라우드 서비스 모델 개요

| 모델 | 정의 | 관리 책임 |
| :--- | :--- | :--- |
| **IaaS (Infrastructure as a Service)** | 가상 서버, 스토리지, 네트워크 등 **하드웨어 인프라**를 서비스로 제공 | OS, 미들웨어, 애플리케이션, 데이터 |
| **PaaS (Platform as a Service)** | 애플리케이션 개발 및 배포를 위한 **플랫폼 환경**을 서비스로 제공 | 애플리케이션, 데이터 |
| **SaaS (Software as a Service)** | 완성된 **소프트웨어 애플리케이션**을 서비스로 제공 | 사용자 데이터 (일부 설정) |

---

## 2. 서비스 스택 관리 책임 비교

![클라우드 서비스 모델 스택](https://www.redhat.com/cms/managed-files/cloud-computing-iaas-paas-saas-diagram-f-2070x1170.png)
_출처: Red Hat_

*   **On-Premise**: 모든 것을 직접 관리 (서버, 네트워크, OS, 미들웨어, 런타임, 앱, 데이터)
*   **IaaS**: 가상화된 하드웨어만 제공. OS부터 위로는 사용자가 관리
*   **PaaS**: OS, 미들웨어, 런타임까지 제공. 사용자는 앱과 데이터만 관리
*   **SaaS**: 완성된 앱까지 제공. 사용자는 데이터만 관리

---

## 3. 각 모델의 특징 및 실무 예시

### 1) IaaS (Infrastructure as a Service)
*   **특징**: 가장 유연하고 제어 권한이 높음. 가상 머신(VM)을 직접 생성하고 OS, 미들웨어 등을 원하는 대로 설치할 수 있음
*   **장점**: 높은 자유도, 세밀한 커스터마이징 가능
*   **단점**: OS부터 위로 모든 것을 관리해야 하므로 관리 부담이 큼
*   **실무 예시**:
    *   **AWS EC2, Google Compute Engine, Azure Virtual Machines**: 가상 서버를 빌려 OS를 설치하고 직접 웹 서버(Nginx), WAS(Tomcat, Spring Boot), DB(MySQL) 등을 구축하여 운영
    *   **활용**: 복잡한 레거시 시스템 마이그레이션, OS 레벨의 커스터마이징이 필요한 경우

### 2) PaaS (Platform as a Service)
*   **특징**: 개발 환경 구축 및 배포 과정을 간소화하여 개발 생산성을 높임. 특정 언어(Java, Python, Node.js)의 런타임 환경을 제공함
*   **장점**: 개발 생산성 향상, 인프라 관리 부담 감소, 빠른 배포
*   **단점**: 특정 플랫폼에 종속될 수 있으며, IaaS만큼의 자유도는 없음
*   **실무 예시**:
    *   **AWS Elastic Beanstalk, Google App Engine, Heroku**: 개발자가 작성한 코드를 업로드하면 플랫폼이 자동으로 서버를 프로비저닝하고 배포, 스케일링까지 관리
    *   **활용**: 웹 애플리케이션, API 서버 개발 및 배포

### 3) SaaS (Software as a Service)
*   **특징**: 이미 개발된 소프트웨어를 웹 브라우저나 앱을 통해 바로 사용할 수 있음. 사용자는 서비스에 접속하여 데이터만 입력하고 활용함
*   **장점**: 가장 낮은 관리 부담, 빠른 도입, 초기 비용 절감
*   **단점**: 커스터마이징이 거의 불가능하며, 데이터 주권 문제가 발생할 수 있음
*   **실무 예시**:
    *   **Google Workspace (Gmail, Drive), Microsoft 365, Slack, Salesforce**: 별도 설치 없이 웹에서 바로 사용
    *   **활용**: 업무 협업 도구, CRM, 이메일 서비스 등

---

## 4. 클라우드 서비스 모델 선택 가이드

| 고려 사항 | IaaS | PaaS | SaaS |
| :--- | :--- | :--- | :--- |
| **관리 부담** | 높음 | 중간 | 낮음 |
| **자유도/유연성** | 높음 | 중간 | 낮음 |
| **개발 생산성** | 낮음 | 높음 | 해당 없음 |
| **비용 효율성** | 사용량에 따라 가변 | 사용량에 따라 가변 | 구독료 |
| **추천 상황** | OS 레벨 제어 필요, 레거시 마이그레이션 | 빠른 개발/배포, 인프라 관리 최소화 | 완성된 솔루션 즉시 사용 |

### 결론
> **클라우드 서비스 모델은 "얼마나 많은 것을 직접 관리할 것인가"에 대한 선택.**
> 서비스의 특성, 개발 팀의 역량, 필요한 제어 수준, 예산 등을 종합적으로 고려하여 가장 적합한 모델을 선택하는 것이 중요
