### IaC (Infrastructure as Code)

**정의**
- **"인프라를 코드로 관리한다"** 는 뜻
- 서버, 네트워크, 데이터베이스 같은 IT 인프라 구성을 사람이 수동으로 클릭해서 만드는 게 아니라, **프로그래밍 코드(스크립트)로 작성하고 실행하여 자동으로 생성/관리**하는 방식

**왜 필요한가? (기존 방식의 문제점)**
- **과거:** 개발자가 "서버 한 대 더 필요해요"라고 하면, 엔지니어가 AWS 콘솔에 들어가서 EC2 생성 버튼 누르고, 보안 그룹 설정하고, IP 할당하고... (수동 작업)
- **문제점:**
    1.  **휴먼 에러:** 사람이 하다 보니 실수로 설정을 빼먹거나 잘못 입력할 수 있음
    2.  **속도 저하:** 서버 100대를 만들어야 한다면 며칠이 걸릴 수도 있음
    3.  **환경 불일치:** 개발 서버랑 운영 서버 설정을 똑같이 맞추기가 어려움 (개발 서버에선 됐는데 운영에선 안됨)

---

### IaC의 핵심 장점

1.  **자동화 & 속도:** 코드 실행 한 번이면 서버 100대도 10분 만에 생성됨
2.  **일관성 (Consistency):** 코드가 같으면 결과물도 항상 같음. 개발/스테이징/운영 환경을 완벽하게 동일하게 유지할 수 있음
3.  **버전 관리 (Git):** 인프라 변경 이력을 Git으로 관리할 수 있음. 누가, 언제, 무엇을 바꿨는지 추적 가능하고, 문제 발생 시 **롤백(Rollback)** 도 쉬움

---

### 선언형 vs 명령형 (접근 방식)

IaC 도구는 크게 두 가지 스타일로 나뉨

#### 1. 선언형 (Declarative) - "결과(What)를 정의"
- **특징:** "나는 웹 서버 3대가 필요해"라고 최종 상태만 적어두면, 도구가 알아서 현재 상태를 확인하고 부족한 만큼 더 만들거나 줄임
- **대표 도구:** **Terraform**, AWS CloudFormation, Kubernetes YAML
- **장점:** 관리가 쉽고 가독성이 좋음
- **예시 (Terraform):**
    ```hcl
    resource "aws_instance" "web" {
      count = 3  # "EC2 인스턴스 3개 만들어줘" (끝)
      ami   = "ami-12345678"
      instance_type = "t2.micro"
    }
    ```

#### 2. 명령형 (Imperative) - "과정(How)을 정의"
- **특징:** "서버를 하나 생성해. 그리고 설정을 바꿔. 그리고 하나 더 생성해." 처럼 순서대로 명령을 내림
- **대표 도구:** **Ansible**, Chef, Puppet (일부 기능)
- **단점:** 중간에 에러가 나면 어디까지 실행됐는지 파악하기 어렵고, 다시 실행했을 때 결과가 달라질 수 있음 (멱등성 보장 노력 필요)
- **예시 (Ansible):**
    ```yaml
    - name: Create instance 1
      command: aws ec2 run-instances ...
    - name: Configure instance 1
      command: ...
    ```

### 실무에서의 활용 예시

**상황: 쇼핑몰 이벤트로 트래픽 폭주 예상**

1.  **기존 방식:**
    - 엔지니어가 밤새 대기하다가 트래픽이 몰리면 손으로 서버를 추가함
    - 이벤트 끝나면 다시 손으로 서버 삭제함 (실수로 안 지우면 요금 폭탄)

2.  **IaC 방식 (Terraform):**
    - `main.tf` 파일에서 `count = 10`으로 수정하고 `terraform apply` 실행
    - 5분 뒤 서버 10대 자동 생성 완료
    - 이벤트 끝나면 `count = 2`로 수정하고 다시 `apply`
    - 8대가 자동으로 삭제됨

### 주요 도구 비교

| 도구 | 유형 | 주요 용도 | 특징 |
| :--- | :--- | :--- | :--- |
| **Terraform** | 선언형 | 인프라 프로비저닝 (생성) | 클라우드(AWS, Azure, GCP) 가리지 않고 다 됨. 사실상 업계 표준. |
| **Ansible** | 명령형 | 구성 관리 (설정) | 이미 만들어진 서버에 Nginx 설치하고 설정 파일 바꾸는 용도로 좋음. |
| **AWS CloudFormation** | 선언형 | 인프라 프로비저닝 | AWS 전용. AWS 서비스랑 찰떡궁합이지만 다른 클라우드는 못 씀. |
| **Kubernetes (YAML)** | 선언형 | 컨테이너 오케스트레이션 | "컨테이너 3개 띄워줘"라고 명세하면 K8s가 알아서 유지함. |
