## 스프링 트랜잭션 AOP 동작 흐름

스프링에서 `@Transactional` 어노테이션을 선언하여 사용하는 **선언적 트랜잭션 관리(Declarative Transaction Management)** 의 내부 동작 원리와 흐름에 대한 정리

---

### 1. 핵심 구성 요소
트랜잭션 AOP가 동작하기 위해서는 다음 3가지 핵심 요소가 협력

1.  **트랜잭션 AOP 프록시 (Transaction AOP Proxy)**
    - 클라이언트의 요청을 가장 먼저 가로채서 트랜잭션 처리 로직(시작, 커밋, 롤백)을 수행
    - 실제 비즈니스 로직(Service) 호출 전후에 트랜잭션 관련 작업을 끼워 넣음
2.  **트랜잭션 매니저 (Transaction Manager)**
    - `PlatformTransactionManager` 인터페이스의 구현체
    - 데이터소스를 통해 커넥션을 생성하고, 트랜잭션의 시작(Begin), 커밋(Commit), 롤백(Rollback)을 실제로 수행
3.  **트랜잭션 동기화 매니저 (Transaction Synchronization Manager)**
    - 쓰레드 로컬(ThreadLocal)을 사용하여 트랜잭션에 사용된 데이터베이스 커넥션을 보관하고 관리
    - 이를 통해 파라미터로 커넥션을 계속 넘기지 않아도, 같은 쓰레드 내에서 동일한 커넥션을 공유

---

### 2. 전체 동작 흐름 (Step-by-Step)

```text
[Client] -> [AOP Proxy] -> [Transaction Manager] -> [DataSource] -> [Sync Manager] -> [Service/Repository]
```

1.  **요청 진입**: 클라이언트가 `@Transactional`이 적용된 서비스 메서드를 호출
2.  **프록시 개입**: 요청을 **트랜잭션 AOP 프록시**가 가로챔
3.  **트랜잭션 시작**: 프록시는 **트랜잭션 매니저**에게 트랜잭션 시작을 요청
4.  **커넥션 획득**: 트랜잭션 매니저는 데이터소스(DataSource)를 통해 DB 커넥션을 획득
5.  **동기화**: 트랜잭션 매니저는 획득한 커넥션을 **트랜잭션 동기화 매니저**에 보관 (이때 `autoCommit`을 `false`로 설정하여 트랜잭션을 시작)
6.  **비즈니스 로직 수행**: 프록시는 실제 서비스(Target)의 메서드를 호출
7.  **커넥션 조회**: 서비스 내부의 리포지토리(Repository) 등 데이터 접근 계층은 **트랜잭션 동기화 매니저**로부터 보관된 커넥션을 꺼내와 사용 (이로써 같은 트랜잭션 내에서 같은 커넥션 사용 보장)
8.  **트랜잭션 종료**:
    - **성공 시**: 비즈니스 로직이 예외 없이 끝나면 프록시는 트랜잭션 매니저에게 **커밋(Commit)** 을 요청
    - **실패 시**: 예외(기본적으로 RuntimeException)가 발생하면 프록시는 트랜잭션 매니저에게 **롤백(Rollback)** 을 요청
9.  **리소스 정리**: 트랜잭션 매니저는 트랜잭션 동기화 매니저에 보관된 커넥션을 제거하고, 커넥션을 닫거나 풀(Pool)에 반환

---

### 3. 상세 개념 Q&A

#### Q1. 트랜잭션 매니저(Transaction Manager)가 왜 필요한가요?
- **기술 추상화**: 데이터 접근 기술(JDBC, JPA, Hibernate 등)마다 트랜잭션을 처리하는 코드가 다름
- 스프링은 `PlatformTransactionManager`라는 인터페이스를 제공하여, 기술이 바뀌더라도 서비스 코드를 수정하지 않고 설정만 변경하면 되도록 추상화
    - JDBC: `DataSourceTransactionManager`
    - JPA: `JpaTransactionManager`

#### Q2. 트랜잭션 동기화 매니저가 왜 필요한가요?
- **커넥션 유지**: 트랜잭션은 하나의 DB 커넥션 안에서 수행되어야 함
- 만약 동기화 매니저가 없다면, 트랜잭션을 유지하기 위해 모든 메서드의 파라미터로 Connection 객체를 계속 넘겨줘야 하는 불편함이 생김
- 스프링은 **ThreadLocal**을 사용하는 트랜잭션 동기화 매니저를 통해, 멀티 쓰레드 환경에서도 안전하게 현재 쓰레드에 할당된 커넥션을 보관하고 꺼내 쓸 수 있게 지원
