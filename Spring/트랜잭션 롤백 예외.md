# 트랜잭션 롤백 예외 (Transaction Rollback Exception)

Spring의 `@Transactional`을 사용할 때, **어떤 예외가 발생하느냐에 따라 트랜잭션이 롤백될 수도 있고, 커밋될 수도 있음** 

이 규칙을 모르면 심각한 데이터 불일치 문제가 발생할 수 있습니다.

---

## 1. Spring의 기본 롤백 정책

Spring 프레임워크는 예외의 종류에 따라 기본적으로 다음과 같이 동작함

| 예외 종류 | 설명 | 기본 동작 |
| :--- | :--- | :--- |
| **Unchecked Exception** | `RuntimeException`을 상속받은 예외 (NPE, IllegalArgumentException 등) | **자동 롤백 (Rollback)** |
| **Checked Exception** | `Exception`을 상속받은 예외 (IOException, SQLException 등) | **커밋 (Commit)** |
| **Error** | 시스템 레벨의 심각한 오류 (OutOfMemoryError 등) | **자동 롤백 (Rollback)** |

> **핵심**: 개발자가 별다른 설정을 하지 않으면, **Checked Exception이 발생해도 트랜잭션은 롤백되지 않고 그대로 DB에 반영(Commit)됨**

---

## 2. 실무에서의 문제 상황 (시나리오)

### 상황: 계좌 이체
A 사용자가 B 사용자에게 10,000원을 이체하는 기능을 개발
1.  A의 잔액을 10,000원 차감 (`UPDATE`)
2.  B의 잔액을 10,000원 증가 (`UPDATE`)
3.  이체 기록 생성 (`INSERT`)

### X 문제 발생: 체크 예외 사용 시 데이터 불일치
개발자가 "잔액 부족" 상황을 알리기 위해 `NotEnoughMoneyException`을 만들었는데, 실수로 `Exception`을 상속받게 함 (Checked Exception)

```java
// Checked Exception 정의
public class NotEnoughMoneyException extends Exception { ... }

@Transactional
public void transfer(String fromId, String toId, long amount) throws NotEnoughMoneyException {
    Member fromMember = memberRepository.findById(fromId);
    Member toMember = memberRepository.findById(toId);
    
    // 1. A의 잔액 차감 시도
    if (fromMember.getBalance() < amount) {
        throw new NotEnoughMoneyException("잔액이 부족합니다."); 
    }
    fromMember.decrease(amount);
    
    // 2. B의 잔액 증가 (여기서 DB 에러가 났다고 가정)
    toMember.increase(amount); 
    
    // 3. 이체 기록 저장
    historyRepository.save(new TransferHistory(fromId, toId, amount));
}
```

만약 2번 과정에서 예상치 못한 `SQLException` (Checked Exception의 일종인 경우)이나 로직 상의 다른 Checked Exception이 발생했다면?
*   Spring은 이를 **"복구 가능한 예외"** 로 판단하고 **롤백하지 않음**
*   결과적으로 **A의 돈은 줄어들었는데(1번 성공), B의 돈은 그대로인(2번 실패) 상태로 트랜잭션이 커밋**되어 버림 -> **금전 사고 발생**

---

## 3. 해결 방안 (Best Practice)

### 방법 1: Unchecked Exception 사용 (권장)
비즈니스 로직에서 발생하는 예외는 대부분 복구가 불가능하거나, 트랜잭션을 롤백해야 하는 경우임. 따라서 커스텀 예외를 만들 때 **`RuntimeException`을 상속**받도록 함

```java
// Unchecked Exception 정의 (권장)
public class NotEnoughMoneyException extends RuntimeException { ... }
```
이렇게 하면 별다른 설정 없이도 예외 발생 시 자동으로 롤백됨

### 방법 2: rollbackFor 옵션 사용
부득이하게 Checked Exception을 던져야 하거나, 라이브러리에서 던지는 Checked Exception을 잡아서 처리해야 한다면 `@Transactional`에 옵션을 명시함

```java
// 모든 예외에 대해 롤백하도록 설정
@Transactional(rollbackFor = Exception.class)
public void transfer(...) { ... }
```

---

## 4. 요약

*   **Unchecked Exception (RuntimeException)**: 시스템이 알아서 롤백해줌 (NPE, 비즈니스 예외 등)
*   **Checked Exception (Exception)**: 시스템이 롤백하지 않음. **반드시 `rollbackFor` 옵션을 쓰거나, 언체크 예외로 변환해서 던져야 함**
*   **실무 팁**: 대부분의 비즈니스 예외는 `RuntimeException`을 상속받아 Unchecked Exception으로 만드는 것이 정신 건강에 좋음
