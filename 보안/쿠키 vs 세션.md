# 쿠키(Cookie) vs 세션(Session) 그리고 JWT

HTTP 프로토콜은 **무상태(Stateless)** 특성을 가지므로, 서버는 클라이언트의 과거 요청을 기억하지 못함 

이를 보완하여 **사용자의 상태(로그인 여부, 장바구니 등)를 유지**하기 위해 쿠키와 세션을 사용함

---

## 1. 개념 및 동작 원리

### 쿠키 (Cookie)
클라이언트(브라우저) 로컬에 저장되는 키-값(Key-Value) 형태의 작은 데이터 파일

*   **동작**:
    1.  서버가 응답 헤더(`Set-Cookie`)에 데이터를 담아 보냄
    2.  브라우저는 이를 저장해두었다가, 매 요청마다 헤더(`Cookie`)에 담아 서버로 전송함
*   **특징**: 사용자 PC에 저장되므로 서버 자원을 사용하지 않음

### 세션 (Session)
중요한 데이터는 **서버 메모리에 저장**하고, 클라이언트에게는 그 데이터에 접근할 수 있는 식별자(**Session ID**)만 쿠키로 부여하는 방식

*   **동작**:
    1.  로그인 성공 시 서버가 사용자 정보를 메모리에 저장하고 `Session ID` 생성
    2.  브라우저 쿠키에 `JSESSIONID=12345` 형태로 저장됨
    3.  요청 시 `JSESSIONID`만 서버로 전송, 서버는 이를 통해 메모리에서 사용자 정보를 찾음
*   **특징**: 중요 정보가 서버에 있어 보안성이 높음

---

## 2. 쿠키 vs 세션 상세 비교

| 구분 | 쿠키 (Cookie) | 세션 (Session) |
| :--- | :--- | :--- |
| **저장 위치** | 클라이언트 (브라우저) | 서버 (메모리, DB 등) |
| **보안** | 취약 (탈취 및 변조 가능) | **우수** (ID만 노출, 데이터는 서버에) |
| **용량 제한** | 약 4KB (도메인당) | 서버 메모리가 허용하는 한 무제한 |
| **속도** | 빠름 (서버 조회 과정 없음) | 비교적 느림 (서버 메모리 조회 필요) |
| **만료 시점** | 설정 가능 (브라우저 종료와 무관) | 브라우저 종료 시 삭제 (설정 가능) |

### 실무 활용 예시
*   **쿠키**:
    *   "오늘 하루 이 창을 열지 않음" 팝업 체크
    *   비로그인 상태의 장바구니 담기 (로그인 시 DB와 병합)
    *   "아이디 저장" 체크박스 기능
*   **세션**:
    *   로그인 사용자 정보 (보안이 중요한 데이터)
    *   관리자 페이지 접근 권한 관리
    *   은행 사이트 (일정 시간 미사용 시 로그아웃)

---

## 3. JWT (JSON Web Token)는 어디에 해당하나요?

JWT는 **쿠키와 세션의 단점을 보완하기 위해 등장한 토큰 기반 인증 방식**. 세션처럼 서버에 상태를 저장하지 않고(Stateless), 쿠키처럼 클라이언트가 토큰을 가지고 있다가 요청 시 제시함

### 세션 방식의 한계 (서버 확장성 문제)
서버가 1대일 때는 세션이 편하지만, 사용자가 많아져 서버를 10대로 늘리면(Scale-out) **세션 불일치 문제**가 발생함 (A서버에 로그인했는데 다음 요청이 B서버로 가면 로그인이 풀림) -> 이를 해결하려면 Redis 같은 별도 세션 저장소가 필요함

### JWT의 등장
*   **동작**: 로그인 성공 시 서버가 **사용자 정보를 암호화(서명)하여 토큰(String)** 으로 만들어 클라이언트에 줌. 서버는 별도 저장소 없이 **토큰의 서명만 검증**하면 됨
*   **장점**:
    *   **무상태(Stateless)**: 서버 확장이 매우 자유로움
    *   **모바일 앱 친화적**: 쿠키를 잘 안 쓰는 앱 환경에서도 헤더에 넣어 사용하기 편함
*   **단점**:
    *   **토큰 탈취 시 대책 어려움**: 세션은 서버에서 지우면 끝이지만, JWT는 만료될 때까지 무효화가 어려움 (Blacklist 관리 필요)
    *   **데이터 크기**: 쿠키/세션 ID보다 길어서 트래픽이 다소 증가함

### 요약
> **보안이 최우선이고 서버 규모가 작다면 `세션`**,
> **대규모 트래픽 처리가 필요하거나 모바일 앱/MSA 환경이라면 `JWT`** 를 주로 사용함.
> `쿠키`는 단순 편의 기능이나 세션 ID/JWT를 담는 운송 수단으로 사용됨
