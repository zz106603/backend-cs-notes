# 이진 트리(Binary Tree)

각 노드가 **최대 2개의 자식 노드(왼쪽, 오른쪽)** 만 가질 수 있는 트리 구조

---

## 1. 왜 필요한가요? (실무 관점)

데이터를 단순히 일렬로 저장하는 배열(Array)이나 리스트(List)와 달리, 계층적인 구조를 표현하거나 **검색 속도를 획기적으로 높이기 위해** 사용함

### 실무 예시: "데이터베이스 인덱스"
*   **상황**: 100만 명의 회원 정보가 저장된 DB에서 `ID = 500000`인 회원을 찾으려고 함
*   **배열(List)이라면?**: 최악의 경우 100만 번을 다 뒤져야 함 (O(N))
*   **이진 탐색 트리(BST)라면?**:
    *   루트 노드(50만)보다 크니까 오른쪽으로 이동 -> 75만보다 작으니까 왼쪽으로 이동...
    *   마치 "스무고개" 하듯이 범위를 절반씩 줄여나가므로, **약 20번(log₂1000000)** 만 비교하면 찾을 수 있음 (O(log N))
*   **결과**: 검색 속도가 비교할 수 없을 정도로 빨라짐. 실제 DB 인덱스(B-Tree)의 기본 원리가 됨

---

## 2. 이진 트리의 종류

### 1) 이진 탐색 트리 (Binary Search Tree, BST)
*   **규칙**:
    *   왼쪽 자식 노드 < 부모 노드
    *   오른쪽 자식 노드 > 부모 노드
*   **특징**: 데이터를 정렬된 상태로 유지하면서 빠르게 검색, 삽입, 삭제할 수 있음
*   **단점**: 데이터가 `1 -> 2 -> 3 -> 4` 순서로 들어오면 한쪽으로만 치우친 **편향 트리(Skewed Tree)** 가 되어, 검색 성능이 O(N)으로 떨어짐 (연결 리스트와 다를 게 없어짐)

### 2) 균형 이진 트리 (Balanced Binary Tree)
*   **목적**: 편향 트리가 되는 것을 막고, 트리의 높이를 항상 O(log N)으로 유지함
*   **종류**:
    *   **AVL 트리**: 엄격하게 균형을 맞춤. 검색은 빠르지만 삽입/삭제 시 회전 연산이 많아 느릴 수 있음
    *   **Red-Black 트리**: AVL보다 균형 조건이 느슨하여 삽입/삭제가 빠름. **Java의 `TreeMap`, `HashMap`(Java 8+) 내부 구현**에 사용됨

### 3) 힙 (Heap)
*   **규칙**: 부모 노드가 자식 노드보다 항상 크거나(최대 힙), 항상 작아야(최소 힙) 함 (좌우 정렬은 신경 안 씀)
*   **용도**: **우선순위 큐(Priority Queue)** 구현에 사용됨
    *   **실무 예시**: 작업 스케줄러에서 "가장 급한 작업"을 O(1) 만에 꺼내올 때 사용함

---

## 3. 순회 방법 (Traversal)

트리의 모든 노드를 한 번씩 방문하는 방법

1.  **전위 순회 (Pre-order)**: 루트 -> 왼쪽 -> 오른쪽
    *   트리를 복사하거나 구조를 그대로 저장할 때 유용함
2.  **중위 순회 (In-order)**: 왼쪽 -> 루트 -> 오른쪽
    *   **이진 탐색 트리(BST)** 를 중위 순회하면 **오름차순으로 정렬된 데이터**를 얻을 수 있음
3.  **후위 순회 (Post-order)**: 왼쪽 -> 오른쪽 -> 루트
    *   하위 디렉토리 용량을 계산하여 상위 디렉토리 용량을 구할 때처럼, 자식 노드 처리가 끝나야 부모를 처리할 수 있을 때 사용함

---

## 4. 요약

| 종류 | 특징 | 주요 용도 |
| :--- | :--- | :--- |
| **이진 탐색 트리 (BST)** | 왼쪽 < 부모 < 오른쪽 | 빠른 검색 (DB 인덱스 원리) |
| **Red-Black 트리** | 균형 잡힌 BST | Java `TreeMap`, `HashMap`, C++ `std::map` |
| **힙 (Heap)** | 부모가 항상 최대/최소 | 우선순위 큐, 작업 스케줄링 |
