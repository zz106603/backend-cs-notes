## NAT 기능
- **사설 IP 환경의 서버가 인터넷과 통신할 수 있도록 주소를 변환하는 기술**
- IP 주소는 공인 IP 주소(Public IP Address)와 사설 IP 주소(Private IP Address)가 존재
- 공인 IP 주소는 고유
- 사설 IP 주소는 고유하지 않고, 특정 사설 네트워크에서만 사용
  - 사설 네트워크는 외부 네트워크에 공개되지 않은 네트워크를 의미
  - 일반적으로 라우터가 할당, 할당 받은 IP 주소는 사설 네트워크 상에서만 유효함
  - 사설 IP 주소만을 가지고 외부 네트워크와 통신하기 어려움
  - 이 문제를 해결하기 위해 라우터 혹은 공유기의 NAT(Network Address Translation) 기능을 사용
- NAT은 IP 주소를 변환하는 기술
  - 사설 IP 주소를 외부 네트워크에 사용되는 공인 IP 주소로 변환하여 외부 네트워크와 통신
- ex)
  - 사설 네트워크에서 출발한 패킷에 존재하는 사설 IP 주소(송신지)가 라우터를 거쳐 공인 IP로 변환
  - 외부 네트워크로부터 출발한 패킷에 존재하는 공인 IP 주소(수신지)는 NAT 기능을 통해서, 사설 IP 주소로 변경되고 사설 네트워크 속 호스트에게 전달
  - NAT에서 주소 변환을 하기 위해 내부적으로 공인 IP 주소와 사설 IP 주소가 대응되어 있는 NAT 테이블 사용
---
### NAT 변환 테이블에서 공인 IP 주소와 사설 IP 주소는 일대일 대응인가?
- 일대일 대응이라면 사설 IP 주소만큼 공인 IP가 필요하기 때문에 한계가 있음
- 일반적으로 일대일 대응하지 않고, NAPT(Network Address Port Translation)이라는 포트 기반의 NAT를 사용
- NAPT 변환 테이블에 IP 주소 쌍과 함께 포트도 기록
```java
| Private IP | Private Port | Public IP | Public Port |
 192.168.10.2      8000        1.2.3.4       8001
 192.168.10.3      8000        1.2.3.4       8002
```
---
### 전체 흐름
`인터넷` -> `NAT / 라우터` -> `Load Balancer` -> `API Gateway` -> `Backend Server`

- NAT 예시
  - 집 공유기
    - 내 노트북: `192.168.0.10`
    - 공유기 공인 IP: `1.2.3.4`
    - 내가 웹 사이트 접속할 때
      - 내 노트북 -> 구글(192.168.0.10 -> 1.2.3.4)
      - NAT 자동 동작
    - 누가 내 PC 서버를 호출하려고 할 때
      - 외부 -> 내 PC
      - 외부는 192.168.0.10 모름
      - 포트 포워딩, NAT 설정 필요
  - 서버
    - 내부 서비스
      - 사내 사용자 -> 사내 API 서버
      - 전부 사설 IP
      - 인터넷 안 낙감
    - 서버가 외부 API 호출
      - 우리 서버 -> 외부 API
      - NAT 자동 처리
    - 외부에서 우리 서버 호출
      - 외부 시스템 -> 우리 서버
      - 외부는 공인 IP만 앎
        - ISP(통신사) 혹은 클라우드로부터 공인 IP를 할당받고 외부 회사로 전달
      - 중간에서 주소를 매핑해야 함
