### DNS (Domain Name System)

**정의**
- 사람이 읽기 쉬운 **도메인 이름(예: www.google.com)** 을 컴퓨터가 이해할 수 있는 **IP 주소(예: 142.250.196.68)** 로 변환해주는 시스템
- 인터넷의 '전화번호부'와 같은 역할을 함

---

### DNS 서버의 종류 (계층 구조)

DNS는 전 세계에 분산된 데이터베이스 시스템이며, 계층적으로 구성되어 있음

1.  **로컬 DNS 서버 (Local DNS Server / Recursive Resolver)**
    - 사용자가 가장 먼저 접근하는 DNS 서버
    - 주로 ISP(통신사: KT, SKT 등)가 제공하거나, 구글(8.8.8.8) 같은 공용 DNS를 사용
    - 사용자의 요청을 받아 대신 IP 주소를 찾아주는 '심부름꾼' 역할을 함

2.  **루트 네임 서버 (Root Name Server)**
    - DNS 계층의 최상위에 위치
    - 전 세계에 13개의 원본 서버가 존재하며, `.com`, `.net`, `.kr` 같은 최상위 도메인(TLD) 서버의 주소를 알고 있음

3.  **TLD 네임 서버 (Top-Level Domain Server)**
    - 최상위 도메인(`.com`, `.kr` 등)을 관리하는 서버
    - 해당 도메인으로 끝나는 사이트들의 권한 네임 서버 주소를 알고 있음

4.  **권한 네임 서버 (Authoritative Name Server)**
    - 실제 도메인 이름과 IP 주소의 매핑 정보를 가지고 있는 최종 서버
    - 가비아, AWS Route53 등 도메인 호스팅 업체가 이 역할을 수행

### DNS 동작 과정 (예시: www.naver.com 접속)

사용자가 브라우저 주소창에 `www.naver.com`을 입력

**1. 캐시 확인 (Caching)**
- **브라우저 캐시:** 브라우저가 이전에 방문한 기록이 있는지 확인
- **OS 캐시 (hosts 파일):** 운영체제의 DNS 캐시를 확인
- **공유기/ISP 캐시:** 공유기나 통신사 DNS 서버의 캐시를 확인
- *캐시에 정보가 있다면 즉시 IP를 반환하고 종료*

**2. 재귀적 질의 (Recursive Query)**
캐시에 정보가 없다면, **로컬 DNS 서버**가 IP를 찾아옴

1.  **로컬 DNS → 루트 서버:** "님, `www.naver.com` IP 아세요?"
2.  **루트 서버 → 로컬 DNS:** "난 모르고, `.com` 관리하는 **TLD 서버** 주소 줄 테니까 걔한테 물어봐."
3.  **로컬 DNS → TLD 서버(.com):** "님, `www.naver.com` IP 아세요?"
4.  **TLD 서버 → 로컬 DNS:** "난 모르고, `naver.com` 관리하는 **권한 네임 서버** 주소 줄 테니까 걔한테 물어봐."
5.  **로컬 DNS → 권한 네임 서버(네이버):** "님, `www.naver.com` IP 아세요?"
6.  **권한 네임 서버 → 로컬 DNS:** "ㅇㅇ 앎. `223.130.195.200`임."
7.  **로컬 DNS → 사용자 PC:** "찾아왔다. 여기 IP 주소."

**3. 결과 저장 및 접속**
- PC는 받아온 IP 주소로 네이버 서버에 접속
- 로컬 DNS 서버는 다음에 또 물어볼까 봐 이 정보를 잠시 **캐시(Cache)** 에 저장

### 주요 DNS 레코드 타입

DNS 서버는 단순히 IP만 저장하는 것이 아니라 다양한 정보를 저장

- **A (Address):** 도메인을 IPv4 주소로 매핑 (가장 기본)
- **AAAA:** 도메인을 IPv6 주소로 매핑
- **CNAME (Canonical Name):** 도메인의 별칭을 지정 (예: `m.naver.com` -> `www.naver.com`)
- **NS (Name Server):** 해당 도메인의 권한 네임 서버 정보를 지정
- **MX (Mail Exchanger):** 메일 서버의 주소를 지정
