# RAID (Redundant Array of Independent Disks)

여러 개의 물리적인 하드 디스크를 하나의 논리적인 디스크로 묶어 관리함으로써 **성능 향상**과 **데이터 안정성(가용성)** 을 동시에 확보하는 기술

---

## 1. 주요 RAID 레벨과 특징

### RAID 0 (Striping)
데이터를 여러 디스크에 분산하여 저장(스트라이핑)
*   **특징**: 데이터를 여러 디스크에서 동시에 읽고 쓸 수 있어 속도가 매우 빠름
*   **단점**: 결함 허용(Fault Tolerance) 기능이 전혀 없음. 디스크가 하나만 고장 나도 전체 데이터를 잃음
*   **실무 예시**: 임시 작업 공간(Scratch Space), 영상 편집용 임시 캐시 등 데이터 손실 위험을 감수하더라도 속도가 최우선인 경우

### RAID 1 (Mirroring)
데이터를 동일하게 복사하여 두 개 이상의 디스크에 저장(미러링)
*   **특징**: 한 디스크가 고장 나도 다른 디스크에 완벽한 복사본이 있어 즉시 복구가 가능함
*   **단점**: 전체 디스크 용량의 50%만 사용할 수 있어 비용이 많이 듬
*   **실무 예시**: 운영체제(OS) 설치 드라이브, 중요한 시스템 설정 파일 저장소

### RAID 5 (Distributed Parity)
데이터와 함께 **패리티(Parity) 정보**를 모든 디스크에 분산 저장 (최소 3개 디스크 필요)
*   **특징**: 디스크 하나가 고장 나도 남은 데이터와 패리티 정보를 이용해 원래 데이터를 복원할 수 있음. 성능과 안정성의 균형이 좋음
*   **단점**: 데이터를 쓸 때마다 패리티를 계산해야 하므로 쓰기 성능이 저하됨
*   **실무 예시**: 일반적인 파일 서버, 백업용 스토리지

### RAID 6 (Double Distributed Parity)
RAID 5의 확장판으로, 패리티 정보를 두 개의 디스크에 나누어 저장 (최소 4개 디스크 필요)
*   **특징**: **동시에 두 개의 디스크가 고장 나도** 데이터를 복구할 수 있어 매우 안전함
*   **실무 예시**: 대용량 스토리지 시스템, 장기간 보관이 필요한 아카이빙 서버

### RAID 10 (1+0, Mirroring + Striping)
RAID 1(미러링)로 묶은 디스크들을 다시 RAID 0(스트라이핑)으로 구성한 방식 (최소 4개 디스크 필요)
*   **특징**: RAID 1의 안정성과 RAID 0의 성능을 모두 가짐. 가장 성능이 뛰어나고 안전함
*   **단점**: 최소 4개의 디스크가 필요하며 가용 용량이 절반으로 줄어들어 비용이 매우 비쌈
*   **실무 예시**: **고성능 데이터베이스(DB) 서버**, 트래픽이 많은 엔터프라이즈 서비스

## 2. RAID 레벨 비교표

| 구분 | RAID 0 | RAID 1 | RAID 5 | RAID 10 |
| :--- | :--- | :--- | :--- | :--- |
| **최소 디스크 수** | 2개 | 2개 | 3개 | 4개 |
| **읽기 성능** | 최상 | 우수 | 우수 | 최상 |
| **쓰기 성능** | 최상 | 보통 | 다소 느림 | 우수 |
| **내결함성** | 없음 | 1개 허용 | 1개 허용 | 2개 허용(각 그룹당 1개) |
| **용량 효율성** | 100% | 50% | (N-1) / N | 50% |

## 3. 실무 적용 가이드: "어떤 상황에 무엇을 쓸까?"

1.  **DB 서버를 구축한다면? -> RAID 10**
    *   데이터베이스는 읽기/쓰기가 빈번하고 데이터 유실이 치명적이므로, 비용이 들더라도 RAID 10을 사용하는 것이 표준

2.  **사내 공유 파일 서버라면? -> RAID 5**
    *   적당한 속도와 적당한 안정성이 필요하며, 디스크 효율을 높여 용량을 확보해야 하므로 RAID 5가 가장 합리적

3.  **웹 서버의 OS 영역이라면? -> RAID 1**
    *   OS 드라이브는 용량이 많이 필요하지 않지만, 고장 시 서버가 멈추므로 안정성이 최우선입니다. 2개의 디스크로 RAID 1을 구성하는 것이 일반적

### 요약
> **RAID는** 속도를 얻으려면 안정성을 포기하거나(RAID 0), 둘 다 얻으려면 비용(디스크 수)을 더 지불해야 합니다(RAID 10). 서비스의 중요도와 예산에 맞춰 적절한 레벨을 선택하는 것이 엔지니어의 핵심 역량
