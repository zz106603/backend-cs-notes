# 멀티 스레딩 (Multi-Threading)

하나의 프로세스(Process) 내에서 여러 개의 실행 흐름(Thread)을 두어 작업을 동시에 처리하는 기술

---

## 1. 왜 필요한가요? (실무 관점)

### 1) 동시 요청 처리 (웹 서버)
*   **상황**: 쇼핑몰 서버에 1,000명의 사용자가 동시에 접속
*   **싱글 스레드라면?**: 한 명의 요청 처리가 끝날 때까지 나머지 999명은 대기해야 함 (줄 서서 기다리는 식당)
*   **멀티 스레드라면?**: 1,000개의 스레드(또는 스레드 풀)가 각 사용자의 요청을 동시에 처리 (직원이 1,000명인 식당)
*   **실무 예시**: **Tomcat(WAS)**은 기본적으로 멀티 스레드 모델을 사용하여 다수의 HTTP 요청을 병렬로 처리

### 2) 백그라운드 작업 (비동기 처리)
*   **상황**: 사용자가 회원가입 버튼을 눌렀음. 가입 환영 이메일을 보내는 데 3초가 걸림
*   **싱글 스레드라면?**: 사용자는 가입 완료 화면을 보기까지 3초 이상 기다려야 함
*   **멀티 스레드라면?**:
    1.  메인 스레드: DB에 회원 정보를 저장하고 즉시 "가입 완료" 응답을 보냄 (0.1초 소요)
    2.  별도 스레드: 백그라운드에서 이메일 발송 작업을 수행함
*   **결과**: 사용자는 0.1초 만에 응답을 받으므로 서비스가 매우 빠르다고 느낌

### 3) 자원 효율성 (I/O Blocking 해결)
*   **상황**: 파일 업로드나 외부 API 호출 같은 I/O 작업은 CPU를 거의 쓰지 않고 대기하는 시간이 김
*   **효과**: I/O 작업으로 대기하는 동안 CPU는 놀지 않고 다른 스레드의 작업을 처리할 수 있어 시스템 자원(CPU)을 알뜰하게 사용할 수 있음

---

## 2. 멀티 스레딩의 특징

### 장점
*   **응답성 향상**: 오래 걸리는 작업을 별도 스레드로 분리하여 메인 스레드가 멈추지 않게 함
*   **자원 공유**: 프로세스끼리는 메모리를 공유하지 않지만, 스레드끼리는 **힙(Heap) 영역을 공유**하므로 데이터를 주고받기가 매우 쉽고 빠름
*   **경제성**: 프로세스를 새로 만드는 것보다 스레드를 생성하고 전환(Context Switching)하는 비용이 훨씬 저렴함

### 단점 및 주의사항 (실무 이슈)
*   **동기화 문제 (Concurrency Issue)**: 여러 스레드가 공유 자원(예: 전역 변수, DB 데이터)에 동시에 접근하여 수정하면 데이터가 꼬일 수 있음 (Race Condition)
    *   *해결*: `synchronized`, `Lock`, `Atomic` 변수 등을 사용하여 접근을 제어해야 함
*   **교착 상태 (Deadlock)**: 두 스레드가 서로 상대방이 가진 자원을 기다리며 무한히 멈춰버리는 현상
*   **디버깅의 어려움**: 버그가 발생했을 때 재현하기가 매우 어렵고, 원인을 찾기 힘듬 (특정 타이밍에만 에러 발생)
*   **컨텍스트 스위칭 오버헤드**: 스레드가 너무 많으면 CPU가 스레드를 전환하느라 실제 작업보다 전환 작업에 더 많은 시간을 쓸 수 있음

## 3. 실무 팁: 스레드 풀 (Thread Pool)

실무에서는 스레드를 필요할 때마다 직접 생성(`new Thread()`)하지 않고, **스레드 풀**을 사용함

### 왜 스레드 풀을 쓰나요?
1.  **생성 비용 절감**: 스레드 생성과 삭제는 OS 입장에서 꽤 무거운 작업. 미리 만들어둔 스레드를 재사용하면 효율적
2.  **리소스 제한**: 스레드를 무제한으로 생성하면 메모리가 부족해져 서버가 죽을 수 있음(OOM). 스레드 풀은 최대 스레드 개수를 제한하여 시스템을 보호

### Java 예시
```java
// 최대 10개의 스레드를 미리 만들어놓고 재사용하는 스레드 풀
ExecutorService executor = Executors.newFixedThreadPool(10);

executor.submit(() -> {
    // 비동기로 처리할 작업 (예: 이메일 발송)
    sendEmail();
});
```

## 4. 요약

| 구분 | 프로세스 (Process) | 스레드 (Thread) |
| :--- | :--- | :--- |
| **정의** | 실행 중인 프로그램의 단위 | 프로세스 내의 실행 흐름 단위 |
| **메모리** | 독립된 메모리 공간 (Code, Data, Heap, Stack) | **Stack만 독립**, 나머지는 공유 (Code, Data, Heap) |
| **통신** | IPC (Inter-Process Communication) 필요 | 공유 메모리를 통해 직접 통신 가능 |
| **비용** | 생성/전환 비용이 큼 | 생성/전환 비용이 작음 |
| **안정성** | 하나가 죽어도 다른 프로세스에 영향 없음 | 하나가 오류 나면 프로세스 전체가 죽을 수 있음 |
