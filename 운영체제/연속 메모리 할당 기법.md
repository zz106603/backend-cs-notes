### 연속 메모리 할당 기법 (Continuous Memory Allocation)

**정의**
- 프로세스(프로그램)를 메모리에 올릴 때, 쪼개지 않고 **연속된 하나의 블록으로 할당**하는 방식
- 책장에 책을 꽂을 때, 1권부터 10권까지 순서대로 빈 공간 없이 꽂는 것과 비슷

**할당 방식의 종류**
1.  **고정 분할 할당 (Fixed Partition Allocation):**
    - 메모리를 미리 정해진 크기(예: 100MB 단위)로 나누어 놓음
    - 구현이 단순하지만, **내부 단편화**가 발생하기 쉬움
2.  **가변 분할 할당 (Variable Partition Allocation):**
    - 프로세스가 필요로 하는 크기만큼 딱 맞춰서 메모리를 할당
    - 메모리 효율은 좋지만, 할당과 해제가 반복되면 **외부 단편화**가 발생

---

### 단편화 (Fragmentation) 문제

메모리 공간이 낭비되는 현상

**1. 내부 단편화 (Internal Fragmentation)**
- **상황:** 할당된 공간이 프로세스가 실제 필요한 공간보다 커서 남는 공간이 생기는 현상.
- **예시:**
    - 메모리 파티션 크기: **100MB** (고정)
    - 들어갈 프로세스 크기: **70MB**
    - **결과:** 100MB 공간을 차지했지만 30MB는 텅 빈 채로 낭비됨. (이 30MB는 다른 프로세스가 쓸 수도 없음)

**2. 외부 단편화 (External Fragmentation)**
- **상황:** 메모리 전체로 보면 빈 공간의 합은 충분하지만, **연속된 공간이 없어서** 프로세스를 할당하지 못하는 현상.
- **예시:**
    - 메모리 전체 빈 공간: **150MB** (50MB + 50MB + 50MB로 흩어져 있음)
    - 들어갈 프로세스 크기: **100MB**
    - **결과:** 150MB나 비어있지만, 연속된 100MB 자리가 없어서 프로세스 실행 불가.

### 동적 메모리 할당 알고리즘 (배치 전략)

가변 분할 할당 방식에서, 여러 개의 빈 공간(Hole) 중 어디에 프로세스를 넣을지 결정하는 방법

**상황 가정**
- 빈 메모리 공간 목록: **[A: 100MB], [B: 500MB], [C: 200MB], [D: 300MB]**
- 새로 들어올 프로세스 크기: **150MB**

**1. 최초 적합 (First Fit)**
- **방식:** 메모리를 처음부터 검색해서, **가장 먼저 발견한** 충분한 공간에 할당
- **예시:** A(100MB)는 작아서 패스 -> **B(500MB)** 발견 -> 바로 할당
- **특징:** 검색 속도가 가장 빠름

**2. 최적 적합 (Best Fit)**
- **방식:** 모든 빈 공간을 검색해서, 프로세스 크기와 **가장 비슷하게 딱 맞는(가장 작은)** 공간에 할당
- **예시:** 모든 공간 검색 -> 150MB를 넣기에 가장 낭비가 적은 **C(200MB)** 에 할당 (50MB만 남음)
- **특징:** 내부 단편화를 줄일 수 있지만, 검색 시간이 오래 걸리고 아주 작은 자투리 공간(외부 단편화)을 많이 만듬

**3. 최악 적합 (Worst Fit)**
- **방식:** 모든 빈 공간을 검색해서, **가장 널널한(가장 큰)** 공간에 할당
- **예시:** 모든 공간 검색 -> 가장 큰 **B(500MB)** 에 할당 (350MB가 남음)
- **특징:** 남은 공간이 커서 다른 프로세스가 들어올 가능성이 높지만, 큰 공간을 쪼개버리기 때문에 나중에 큰 프로세스가 들어올 자리가 없어질 수 있음

### Q&A: 메모리 할당은 누가 결정하나요?

**Q. 이 메모리 할당 방식은 사용자가 선택할 수 있나요?**
- **아니요, 전적으로 운영체제(OS)가 결정하고 수행**
- 메모리 관리는 운영체제의 커널(Kernel)이 담당하는 가장 핵심적인 기능 중 하나. Windows나 macOS 같은 운영체제를 설치할 때 이미 그 안에 어떤 알고리즘으로 메모리를 관리할지 프로그래밍되어 있음
- 일반 사용자는 물론이고, 응용 프로그램 개발자도 "내 프로그램은 최적 적합(Best Fit)으로 메모리를 할당해줘"라고 OS에 직접 명령할 수 없음

**Q. 현대 운영체제(Windows, macOS)도 이 방식을 쓰나요?**
- **대부분 쓰지 않음**
- 앞서 설명한 '연속 메모리 할당'은 과거의 방식이거나 임베디드 시스템 등 특수한 환경에서 주로 쓰입니다.
- 현대의 범용 운영체제는 **페이징(Paging)** 이라는 불연속 메모리 할당 기법을 주로 사용합니다. 페이징은 메모리를 일정한 크기의 조각(Page)으로 잘게 나누어 관리하기 때문에 외부 단편화 문제가 거의 발생하지 않음
