# 스레드 (Thread) vs 코루틴 (Coroutine)

비동기 작업과 동시성 처리를 위해 사용되는 두 기술의 개념과 동작 원리, 그리고 성능 차이를 비교

---

## 1. 기본 개념

### 스레드 (Thread)
프로세스 내에서 실행되는 최소 작업 단위로, 운영체제(OS) 커널에 의해 관리되는 **커널 수준의 스레드**

*   **특징**: 각 스레드는 고유한 **스택(Stack)** 영역을 할당받으며(약 1MB), OS가 직접 스케줄링 함
*   **한계**: 생성 및 전환(Context Switching) 비용이 크고, 스레드가 많아질수록 메모리 점유율이 급격히 높아짐

### 코루틴 (Coroutine)
스레드 위에서 실행되는 **가벼운 스케줄링 단위**로, 운영체제가 아닌 언어나 라이브러리 차원에서 관리되는 **사용자 수준의 스레드**

*   **특징**: 스레드 하나에서 여러 개의 코루틴을 번갈아 실행할 수 있으며, 특정 지점에서 실행을 멈추고(Suspend) 나중에 재개(Resume)할 수 있음
*   **장점**: 메모리 사용량이 매우 적고(수 KB), OS의 개입 없이 전환되므로 비용이 매우 저렴함

---

## 2. 주요 차이점 비교

| 구분 | 스레드 (Thread) | 코루틴 (Coroutine) |
| :--- | :--- | :--- |
| **관리 주체** | OS 커널 (Kernel) | 사용자/라이브러리 (Application) |
| **메모리 할당** | 고정된 스택 공간 (약 1MB) | 필요 시 힙(Heap) 공간 활용 (수 KB) |
| **컨텍스트 스위칭** | OS가 관여하여 비용이 큼 | 직접 상태를 전환하여 비용이 매우 적음 |
| **동작 방식** | **Preemptive** (OS가 강제 전환) | **Cooperative** (스스로 양보/중단) |
| **작업 중단** | 블로킹(Blocking) 시 스레드 점유 | 서스펜드(Suspend) 시 스레드 반환 |

---

## 3. 핵심 동작: 블로킹 vs 일시 중단

### 스레드의 블로킹 (Blocking)
스레드에서 네트워크 요청을 보내면, 응답이 올 때까지 해당 스레드는 아무것도 못 하고 대기해야 함. 이 대기 시간 동안 CPU 자원이 낭비됨

### 코루틴의 일시 중단 (Suspend)
코루틴에서 네트워크 요청을 보내면, **"잠시 멈춤(Suspend)"** 상태가 되면서 자신을 실행하던 스레드를 다른 코루틴에게 양보함. 응답이 오면 다시 해당 스레드(혹은 다른 여유 스레드)에서 하던 일을 이어서 함

## 4. 실무 예시: "10,000개의 API 요청 처리"

### 스레드 방식 (Java 기준)
1만 개의 요청을 처리하기 위해 1만 개의 스레드를 생성하면, 스레드당 1MB씩 총 **10GB의 메모리**가 필요함. 또한 수많은 스레드 간의 컨텍스트 스위칭으로 인해 CPU 성능의 상당 부분이 관리 비용으로 소모됨

### 코루틴 방식 (Kotlin 기준)
1만 개의 코루틴을 생성해도 실제로는 수십 개의 스레드만 사용하여 작업을 처리함. 각 코루틴은 I/O 대기 시간에 스레드를 반환하므로, **적은 메모리(몇십 MB)** 로도 1만 개의 동시 작업을 효율적으로 처리할 수 있음

```kotlin
// 10,000개의 작업을 동시에 실행해도 메모리 부하가 거의 없음
runBlocking {
    repeat(10_000) {
        launch {
            delay(1000) // 1초 동안 대기 (스레드를 차단하지 않음)
            println("Task completed")
        }
    }
}
```

## 5. 결론: 언제 무엇을 써야 할까?

*   **코루틴 사용 추천**:
    *   네트워크 요청(API), 파일 I/O 등 **대기 시간이 많은 작업**이 대량으로 발생할 때
    *   안드로이드처럼 UI 스레드를 차단하면 안 되는 환경에서 비동기 작업을 처리할 때
*   **스레드 사용 추천**:
    *   복잡한 연산, 대규모 데이터 가공 등 **CPU 자원을 집중적으로 사용**해야 하는 작업 (이때는 스레드 풀을 활용)

### 요약
> **코루틴은 "스레드를 더 잘게 쪼개서 쓰는 기술"이 아니라, "스레드가 쉬지 않고 일하게 만드는 효율적인 작업 관리 기술".**
> 대규모 동시성 처리가 필요한 현대 백엔드 및 모바일 개발에서 필수적인 패턴
