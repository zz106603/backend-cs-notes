### 단일 프로그래밍, 멀티 프로그래밍, 멀티 태스킹

운영체제가 프로세스를 어떻게 관리하는지에 대한 발전 과정을 나타내는 핵심 개념들

---

### 1. 단일 프로그래밍 (Single-Programming)

- **개념:** 한 번에 **오직 하나의 프로그램**만 메모리에 올라와 실행됨
- **동작:** 현재 프로그램이 끝나야만 다음 프로그램을 실행할 수 있음 (예: MS-DOS)
- **문제점: CPU 낭비**
    - 프로그램이 파일 읽기/쓰기 같은 **I/O 작업을 할 때, CPU는 아무 일도 안 하고 멍하니 기다림**
    - 이는 마치 요리사 한 명이 재료가 배달될 때까지 아무것도 안 하고 주방에 서 있는 것과 같음

---

### 2. 멀티 프로그래밍 (Multi-Programming)

- **개념:** **여러 개의 프로그램**을 동시에 메모리에 올려놓고, CPU가 쉴 틈이 없도록 만드는 방식
- **목표:** **CPU 이용률 극대화**
- **동작 (CPU 전환 시점: I/O 대기):**
    1.  프로그램 A가 실행되다가 I/O 작업을 만나면 대기 상태가 됨
    2.  이때 CPU는 놀지 않고, 바로 프로그램 B로 전환하여 작업을 계속함
    3.  B가 끝나거나 I/O 대기에 걸리면 다시 다른 프로그램으로 전환함
- **문제점: 응답 시간 지연**
    - 만약 프로그램 A가 I/O 작업 없이 CPU만 계속 쓰는 계산 집약적인 작업이라면, 다른 프로그램들은 하염없이 기다려야 함 (CPU 독점)

---

### 3. 멀티 태스킹 (Multi-Tasking) / 시분할 시스템 (Time-Sharing)

- **개념:** 멀티 프로그래밍의 확장판으로, **아주 짧은 시간(Time Slice)** 단위로 여러 프로세스에 CPU를 번갈아 할당하는 방식
- **목표:** **사용자 응답 시간 최소화**
- **동작 (CPU 전환 시점: 타임 슬라이스 만료):**
    - I/O 대기가 없더라도, 각 프로세스는 자신에게 할당된 시간(예: 10ms)이 다 되면 강제로 CPU를 빼앗기고 다음 프로세스에게 순서를 넘김
    - 이 전환 속도가 매우 빨라서, 사용자는 마치 **여러 프로그램이 동시에 실행되는 것처럼** 느낌
- **결론:** 오늘날 우리가 쓰는 대부분의 운영체제(Windows, macOS, Linux)는 멀티 태스킹 시스템

---

### 요약 비교표

| 구분 | 목표 | CPU 전환 시점 | 비유 (요리사 1명) |
| :--- | :--- | :--- | :--- |
| **단일 프로그래밍** | 단순 실행 | 프로그램 종료 시 | 요리 A 완성 후 요리 B 시작 |
| **멀티 프로그래밍** | **CPU 이용률 극대화** | **I/O 대기 발생 시** | A 요리 끓이는 동안 B 요리 재료 손질 |
| **멀티 태스킹** | **사용자 응답 시간 최소화** | **타임 슬라이스 만료 시** | A, B, C 요리에 1분씩 번갈아 신경 씀 |

**핵심 관계:**
- **멀티 태스킹은 멀티 프로그래밍의 한 종류**
- 모든 멀티 태스킹 시스템은 멀티 프로그래밍 시스템이지만, 그 역은 성립하지 않음 (시간 분할이 없으면 그냥 멀티 프로그래밍)
