### 무중단 배포 (Zero-Downtime Deployment)

**정의**
- 서비스를 중단하지 않고(다운타임 없이) 새로운 버전의 애플리케이션을 사용자에게 배포하는 기술
- 사용자는 배포가 진행되는 동안에도 평소와 다름없이 서비스를 이용할 수 있음

---

### 주요 배포 전략 및 실무 예시

#### 1. 롤링 배포 (Rolling Deployment)

**개념**
- 운영 중인 서버(인스턴스)를 **하나씩 또는 그룹 단위로 순차적으로 교체**하는 방식
- 구버전과 신버전이 공존하는 시간이 김

**장점**
- 추가적인 인프라(서버) 비용이 거의 들지 않음 (기존 서버를 재활용)
- 배포 중 문제가 발생하면 해당 서버만 롤백하면 되므로 관리가 비교적 쉬움

**단점**
- 배포 중인 서버는 트래픽을 받을 수 없으므로, 남은 서버들의 부하가 일시적으로 증가
- 구버전과 신버전이 공존하므로 **하위 호환성(Backward Compatibility)** 유지가 필수적입니다.

**실무 예시**
> **상황:** 스타트업 A사는 비용 절감을 위해 최소한의 서버(EC2 3대)로 서비스를 운영 중
>
> **적용:**
> 1. 로드 밸런서에서 1번 서버를 제외 (트래픽 차단)
> 2. 1번 서버에 신규 버전을 배포하고 재시작
> 3. 1번 서버가 정상화되면 다시 로드 밸런서에 연결
> 4. 2번, 3번 서버에 대해서도 위 과정을 반복
>
> **결과:** 추가 서버 비용 없이 배포를 완료했지만, 배포 중에는 2대의 서버가 3대분의 트래픽을 감당해야 함

---

#### 2. 블루/그린 배포 (Blue/Green Deployment)

**개념**
- **Blue(구버전)** 와 동일한 환경의 **Green(신버전)** 서버 세트를 별도로 구축
- 배포 준비가 완료되면 로드 밸런서나 라우터의 설정을 변경하여 **트래픽을 한순간에 Green으로 전환**

**장점**
- 배포 속도가 매우 빠름 (트래픽 전환만 하면 됨)
- 문제 발생 시 트래픽을 다시 Blue로 돌리면 되므로 **롤백이 즉각적이고 확실**
- 운영 환경과 동일한 환경에서 신버전을 미리 테스트해볼 수 있음

**단점**
- 서버 자원이 2배로 필요하므로 **비용 부담**이 큼

**실무 예시**
> **상황:** 대기업 B사는 블랙 프라이데이 이벤트를 앞두고 대규모 UI 개편을 진행. 배포 실패 시 매출 타격이 크므로 즉각적인 롤백이 중요
>
> **적용:**
> 1. 현재 운영 중인 'Blue 그룹'(서버 100대) 옆에 신규 코드가 배포된 'Green 그룹'(서버 100대)을 생성
> 2. 내부망에서 Green 그룹에 접속하여 기능이 정상 작동하는지 최종 점검
> 3. 새벽 3시, 로드 밸런서 설정을 변경하여 모든 사용자 트래픽을 Green 그룹으로 돌림
> 4. 모니터링 후 문제가 없으면 Blue 그룹을 종료하여 자원을 반납

#### 3. 카나리 배포 (Canary Deployment)

**개념**
- 광산의 카나리아처럼 위험을 감지하기 위해 **소수의 사용자에게만 먼저 신버전을 배포**하는 방식
- 트래픽의 일부(예: 5% -> 10% -> 50% -> 100%)를 단계적으로 신버전으로 전환

**장점**
- 문제 발생 시 영향받는 사용자를 최소화할 수 있음
- 실제 운영 환경에서의 **A/B 테스트**나 성능 모니터링에 유용

**단점**
- 트래픽 제어 및 모니터링을 위한 인프라 구성이 복잡
- 롤링 배포와 마찬가지로 구버전/신버전 호환성을 유지해야 함

**실무 예시**
> **상황:** 글로벌 서비스 C사는 새로운 추천 알고리즘을 도입하려 함. 하지만 실제 사용자 반응이나 서버 부하를 예측하기 어려움
>
> **적용:**
> 1. 전체 트래픽의 1%만 신규 알고리즘이 적용된 서버(Canary)로 보냄 (주로 사내 직원이나 특정 지역 사용자)
> 2. 로그를 분석하여 에러율과 응답 속도를 확인
> 3. 문제가 없다면 트래픽 비중을 10%, 30%, 50%로 점진적으로 늘림
> 4. 최종적으로 100% 트래픽이 신규 서버로 가게 되면 배포를 완료

### 요약: 어떤 전략을 선택해야 할까요?

| 전략 | 비용 | 배포 속도 | 롤백 난이도 | 추천 상황 |
| :--- | :--- | :--- | :--- | :--- |
| **롤링** | 낮음 | 느림 | 보통 | 인프라 비용이 제한적이고, 배포 변경 사항이 크지 않을 때 |
| **블루/그린** | 높음 | 빠름 | 쉬움 | 대규모 업데이트, 즉각적인 롤백이 중요할 때, 자금 여유가 있을 때 |
| **카나리** | 중간 | 느림 | 보통 | 신기능에 대한 리스크가 크거나, A/B 테스트가 필요할 때 |
