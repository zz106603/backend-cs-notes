# IaaS / PaaS / SaaS

## 개요

클라우드 서비스는  
“어디까지를 사용자가 직접 운영하고, 어디까지를 클라우드 사업자가 관리하는가”에 따라 구분됨

핵심은 다음과 같다.

- 관리 책임 범위
- 제어 수준
- 운영 부담

---

# 전체 구조

| 구분 | 사용자가 관리 | 클라우드 사업자가 관리 |
|---|---|---|
| SaaS | 거의 없음 | 대부분 |
| PaaS | 애플리케이션, 데이터 | 플랫폼, 인프라 |
| IaaS | OS 이상 대부분 | 물리 인프라 |

---

# IaaS (Infrastructure as a Service)

## 개념

인프라 자원을 제공하는 형태

사용자는 OS부터 애플리케이션까지 직접 관리함

---

## 관리 범위

### 사용자 관리

- OS
- Runtime
- Middleware
- Application
- 보안 설정
- 네트워크 일부 설정

### 클라우드 사업자 관리

- 물리 서버
- 스토리지
- 네트워크 인프라
- 가상화 환경

---

## AWS 예시

- Amazon EC2
- Amazon VPC
- Amazon EBS

---

## 특징

| 항목 | 설명 |
|---|---|
| 자유도 | 매우 높음 |
| 운영 부담 | 큼 |
| 제어 수준 | 높음 |
| 유연성 | 높음 |
| 실무 활용 | 매우 많음 |

---

## 실무 예시

### 일반적인 백엔드 운영 구조

- EC2 생성
- Ubuntu 설치
- Docker 설치
- Nginx 구성
- Spring Boot 실행

→ 전형적인 IaaS 구조

---

# PaaS (Platform as a Service)

## 개념

애플리케이션 실행 플랫폼까지 제공하는 형태

개발자는 애플리케이션과 데이터에 집중하고,   플랫폼 및 인프라 운영은 클라우드 사업자가 담당함

---

## 관리 범위

### 사용자 관리

- 애플리케이션
- 데이터
- 비즈니스 로직

### 클라우드 사업자 관리

- Runtime
- Middleware
- OS
- 서버
- 네트워크
- 일부 운영 작업

---

## AWS 예시

- AWS Elastic Beanstalk
- Amazon RDS
- AWS Lambda

---

## 특징

| 항목 | 설명 |
|---|---|
| 운영 부담 | 감소 |
| 개발 속도 | 빠름 |
| 생산성 | 높음 |
| 자유도 | 상대적으로 낮음 |
| 세부 제어 | 제한적 |

---

## 실무 예시

### RDS 사용

개발자는 다음에 집중

- SQL
- 테이블 설계
- 데이터 관리

AWS는 다음을 관리

- 백업
- Failover
- 패치
- Multi-AZ
- 스토리지 운영

→ DB 운영 플랫폼 자체를 AWS가 제공

---

# SaaS (Software as a Service)

## 개념

완성된 소프트웨어 자체를 제공하는 형태

사용자는 기능만 사용하며, 인프라와 애플리케이션 운영은 서비스 제공자가 담당

---

## 예시

- Google Docs
- Slack
- Notion
- GitHub

---

## 관리 범위

### 사용자

- 기능 사용

### 서비스 제공자

- 애플리케이션
- Runtime
- OS
- 서버
- 네트워크
- 운영 전체

---

## 특징

| 항목 | 설명 |
|---|---|
| 사용 편의성 | 매우 높음 |
| 운영 부담 | 거의 없음 |
| 즉시 사용 가능 | 가능 |
| 자유도 | 매우 낮음 |
| 내부 제어 | 불가능 |

---

# 비교 정리

| 항목 | IaaS | PaaS | SaaS |
|---|---|---|---|
| 제어 수준 | 높음 | 중간 | 낮음 |
| 운영 부담 | 큼 | 중간 | 매우 낮음 |
| 자유도 | 높음 | 중간 | 낮음 |
| 생산성 | 중간 | 높음 | 매우 높음 |
| 대표 예시 | EC2 | RDS / Lambda | Notion / Slack |

---

# Managed Service

## 개념

AWS가 운영 책임 일부를 대신 수행하는 서비스

대표적으로:

- RDS
- Lambda
- SQS
- DynamoDB

---

## 예시 비교

### 직접 MySQL 운영 (IaaS)

EC2 내부에서 직접 수행해야 하는 작업

- MySQL 설치
- 백업 설정
- 패치
- 장애 대응
- Failover 구성

---

### RDS 사용 (Managed Service)

AWS가 제공하는 기능

- 자동 백업
- Failover
- 패치
- 스토리지 관리
- Multi-AZ

개발자는 데이터 사용에 집중 가능

---

# 헷갈리는 개념

## RDS는 완전한 PaaS인가?

완전히 자동화된 구조는 아님

일부 설정은 직접 관리해야 함

하지만 일반적으로는 Managed DB Platform 형태로 보고 PaaS 성격으로 분류함

---

## Kubernetes는 PaaS인가?

상황에 따라 다름

### 직접 구축 Kubernetes

- IaaS 성격 강함

### Managed Kubernetes (EKS)

- PaaS 성격 증가

즉, 실무에서는 경계가 명확하지 않은 경우가 많음

---

# 실무 관점

실무에서는 “어디까지를 AWS에게 맡길 것인가”가 중요함

---

## 스타트업 초기

Managed Service 적극 사용

이유

- 운영 인력 부족
- 빠른 개발 필요
- 운영 자동화 중요

대표 예시

- RDS
- S3
- Lambda
- SQS

---

## 대규모 기업

직접 운영 또는 커스텀 구성을 선택하는 경우 존재

이유

- 비용 최적화
- 특수 요구사항
- 세밀한 제어 필요
- 자체 운영 정책

---

# 면접 핵심 포인트

## IaaS / PaaS / SaaS 차이

주요 비교 기준

- 관리 책임 범위
- 제어 수준
- 운영 부담
- 자유도

---

## Managed Service 사용 이유

- 운영 부담 감소
- 생산성 향상
- 장애 대응 자동화
- 개발 집중 가능

---

# 핵심 요약

## IaaS

- 인프라 제공
- OS 이상 직접 관리
- 자유도 높음

---

## PaaS

- 플랫폼 제공
- 운영 부담 감소
- 코드 중심 개발 가능

---

## SaaS

- 완성된 소프트웨어 제공
- 사용자는 기능만 사용
- 운영 책임 거의 없음
