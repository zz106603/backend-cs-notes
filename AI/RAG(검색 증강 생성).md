### RAG (Retrieval-Augmented Generation, 검색 증강 생성)

**정의**
- **"검색(Retrieval)을 통해 얻은 정보를 바탕으로(Augmented) 답변을 생성(Generation)하는 기술"**
- LLM(거대언어모델)이 학습하지 않은 **최신 정보**나 **기업 내부의 비공개 데이터**를 활용하여 정확한 답변을 생성하도록 돕는 프레임워크

**비유: "오픈북 테스트"**
- **일반 LLM:** 공부한 내용(학습 데이터)만 가지고 시험을 봄. 모르는 게 나오면 아무 말이나 지어냄 (환각 현상)
- **RAG:** 교과서(우리 회사 데이터)를 옆에 펴두고, 관련된 내용을 찾아서 읽어보고 답을 씀. 훨씬 정확하고 근거가 있음

---

### 왜 필요한가요? (LLM의 한계 극복)

1.  **환각(Hallucination) 방지:** "세종대왕이 맥북을 던진 사건"처럼 사실이 아닌 내용을 그럴듯하게 말하는 것을 막아줌 (근거 자료를 주니까)
2.  **최신 정보 반영:** LLM은 학습 시점(예: 2023년) 이후의 일은 모릅니다. RAG를 쓰면 오늘 뉴스도 검색해서 답변할 수 있음
3.  **데이터 보안:** 우리 회사의 기밀 문서를 LLM에게 학습시키지 않아도(외부 유출 없이), 검색해서 답변하게 만들 수 있음

---

### 동작 원리 (아키텍처)

사용자가 "우리 회사 재택근무 규정이 뭐야?"라고 물었을 때의 흐름

1.  **질문 임베딩 (Embedding):** 사용자의 질문을 컴퓨터가 이해할 수 있는 **숫자 벡터(Vector)** 로 변환
2.  **검색 (Retrieval):** 미리 구축해둔 **벡터 데이터베이스(Vector DB)** 에서 질문과 가장 유사한 문서 조각(Chunk)을 찾음
    - 예: "재택근무는 주 2회 가능하며..." 라는 문단이 검색됨
3.  **프롬프트 구성 (Augmentation):** 검색된 문서 조각을 프롬프트에 끼워 넣음
    - 프롬프트: "다음 문서를 참고해서 답변해줘. [문서: 재택근무는 주 2회...] 질문: 재택근무 규정이 뭐야?"
4.  **답변 생성 (Generation):** LLM이 완성된 프롬프트를 보고 정확한 답변을 생성

---

### 핵심 기술 요소 (백엔드 개발자 관점)

#### 1. 임베딩 (Embedding)
- 텍스트를 고차원의 벡터(숫자 배열)로 변환하는 기술
- 의미가 비슷한 문장은 벡터 공간에서 서로 가까운 위치에 존재하게 됨
- OpenAI의 `text-embedding-3-small` 같은 모델을 API로 호출해서 사용함

#### 2. 벡터 데이터베이스 (Vector DB)
- 임베딩된 벡터 데이터를 저장하고, **유사도 검색(Similarity Search)** 을 빠르게 수행하는 전용 DB
- **종류:**
    - **Pinecone:** 관리형 서비스(SaaS), 사용하기 가장 쉬움
    - **Milvus, Weaviate:** 오픈소스, 대규모 처리에 강함
    - **pgvector:** PostgreSQL의 확장 기능 (기존 RDB 인프라 활용 가능)
    - **Elasticsearch:** 키워드 검색과 벡터 검색을 하이브리드(Hybrid)로 사용할 때 강력함

---

### 실무 예시: 사내 규정 챗봇 만들기

**준비 단계 (Indexing)**
1.  사내 규정 PDF 파일 100개를 텍스트로 추출함
2.  텍스트를 500자 단위로 자름 (Chunking)
3.  각 조각을 임베딩 API에 보내 벡터로 변환
4.  벡터와 원본 텍스트를 Vector DB에 저장

**서비스 단계 (Serving)**
1.  **사용자:** "연차는 며칠 전에 신청해야 해?"
2.  **백엔드 서버:** 질문을 벡터로 변환 -> Vector DB 검색 -> 가장 유사한 '연차 규정' 문단 3개 획득
3.  **백엔드 서버:** LLM에게 "이 문단들을 보고 답변해줘"라고 요청
4.  **LLM:** "규정에 따르면 연차는 최소 3일 전에 신청해야 합니다."

### 요약

| 구분 | 일반 LLM | RAG (검색 증강 생성) |
| :--- | :--- | :--- |
| **지식 출처** | 학습된 데이터 (과거) | **외부 데이터베이스 (실시간)** |
| **정확도** | 환각 발생 가능성 높음 | **근거 기반이라 정확함** |
| **비용** | 파인튜닝(재학습) 비쌈 | **비교적 저렴하고 구축 쉬움** |
| **주요 기술** | 프롬프트 엔지니어링 | **임베딩, 벡터 DB, 검색** |
