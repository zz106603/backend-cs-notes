# K6, Prometheus, Grafana: 성능 테스트 및 모니터링 도구

현대적인 백엔드 시스템 운영에서 **성능 테스트(부하 테스트)** 와 **모니터링(관측성)** 은 필수적 

이 문서에서는 대표적인 오픈소스 도구인 **K6**, **Prometheus**, **Grafana**의 개념과 차이점, 그리고 함께 사용하는 이유를 정리

---

## 1. 각 도구의 개념 및 역할

### K6 (부하 테스트 도구)
*   **개념** 
    * 개발자 친화적인 오픈소스 부하 테스트(Load Testing) 도구
    * Go 언어로 작성되었으며, 테스트 스크립트는 **JavaScript(ES6)** 로 작성
*   **역할**
    *   서버에 가상의 사용자(Virtual Users, VUs)를 생성하여 트래픽을 발생시킴
    *   API 응답 시간, 초당 요청 수(RPS), 에러율 등을 측정하여 시스템의 성능 한계를 파악
*   **특징**
    *   가볍고 빠르며, CI/CD 파이프라인에 통합하기 쉬움
    *   JMeter보다 스크립트 작성이 직관적이고 버전 관리가 용이함

### Prometheus (메트릭 수집 및 저장)
*   **개념**
    * 시계열 데이터베이스(TSDB)를 내장한 오픈소스 모니터링 시스템
*   **역할**:
    *   **Pull 방식**으로 대상 서버(Exporter)로부터 주기적으로 메트릭(CPU 사용량, 메모리, 요청 수 등)을 긁어옴(Scraping)
    *   수집된 데이터를 저장하고, PromQL이라는 쿼리 언어를 통해 데이터를 조회할 수 있게 함
*   **특징**:
    *   쿠버네티스(Kubernetes) 환경 모니터링의 사실상 표준
    *   강력한 알림(Alerting) 기능을 제공함

### Grafana (데이터 시각화)
*   **개념**: 다양한 데이터 소스(Prometheus, MySQL, Elasticsearch 등)를 연결하여 대시보드로 시각화해주는 도구
*   **역할**:
    *   Prometheus가 수집한 데이터를 예쁜 그래프, 차트, 게이지 등으로 보여줌
    *   운영자가 한눈에 시스템 상태를 파악할 수 있도록 도움
*   **특징**:
    *   매우 유연한 대시보드 커스터마이징이 가능함
    *   다양한 플러그인을 지원하여 확장성이 뛰어남

## 2. 도구 간의 관계 및 차이점

| 구분 | **K6** | **Prometheus** | **Grafana** |
| :--- | :--- | :--- | :--- |
| **핵심 목적** | **공격 (Attack)** | **수집 (Collect)** | **관찰 (Observe)** |
| **주요 기능** | 트래픽 발생, 부하 테스트 | 메트릭 수집, 저장, 알림 | 데이터 시각화, 대시보드 |
| **데이터 흐름** | 트래픽 생성 -> 서버 | 서버 -> Prometheus (Pull) | Prometheus -> Grafana (Query) |
| **사용 시점** | 개발/테스트 단계, 배포 전 검증 | 운영 단계 (상시 모니터링) | 운영 단계 (상시 모니터링) |

## 3. 왜 이 3가지를 함께 사용하나요?

이 세 도구는 **"부하 테스트 환경 구축"** 을 위해 환상의 짝꿍처럼 함께 사용됨

### 시나리오: "우리 서버가 몇 명까지 버틸 수 있을까?"

1.  **K6로 공격**: 개발자는 K6 스크립트를 실행하여 서버에 점진적으로 부하를 줌 (예: 100명 -> 1000명 -> 5000명)
2.  **Prometheus로 기록**: 서버가 힘들어하는 동안, Prometheus는 서버의 CPU가 치솟고 메모리가 부족해지는 상황을 실시간으로 수집하여 저장. 또한 K6가 보내주는 테스트 결과 데이터도 수집할 수 있음
3.  **Grafana로 확인**: 개발자는 Grafana 대시보드를 보면서 분석함
    *   *"동시 접속자 3000명이 되니까 응답 속도가 2초를 넘어가네?"*
    *   *"이때 DB CPU가 100%를 쳤구나. 여기가 병목이네!"*

### 결론
*   **K6**만 쓰면: 결과가 텍스트로만 나와서 시간대별 변화를 보기 어려움
*   **Prometheus**만 쓰면: 데이터를 숫자로만 봐야 해서 직관적이지 않음
*   **Grafana**만 쓰면: 보여줄 데이터가 없음

따라서 **K6(부하 발생) + Prometheus(데이터 저장) + Grafana(시각화)** 조합을 통해 **실시간으로 부하 테스트 결과를 모니터링하고 분석**하는 환경을 구축하는 것이 업계 표준(Best Practice) 중 하나
