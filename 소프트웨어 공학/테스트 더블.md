### 테스트 더블 (Test Double)

**정의**
- 영화 촬영 시 배우 대신 위험한 연기를 하는 '스턴트 더블(Stunt Double)'에서 유래한 용어
- 테스트를 진행할 때 **실제 객체 대신 사용되는 모든 가짜 객체**를 통칭
- 데이터베이스 연결, 외부 API 호출 등 테스트하기 어렵거나 비용이 많이 드는 의존성을 대체하여 테스트의 속도와 안정성을 높이는 데 사용

**사용 이유**
1.  **외부 의존성 제거:** DB, 네트워크 등 외부 요인에 의해 테스트가 실패하는 것을 방지 (비결정적 요인 제거)
2.  **속도 향상:** 실제 DB나 API를 호출하지 않으므로 테스트 실행 속도가 매우 빨라짐
3.  **특정 상황 시뮬레이션:** 예외 발생, 타임아웃 등 실제 환경에서 재현하기 어려운 상황을 쉽게 테스트할 수 있음

### 테스트 더블의 5가지 종류 및 예시

테스트 더블은 역할과 복잡도에 따라 크게 5가지로 분류됨 (Gerard Meszaros의 분류)

#### 1. 더미 (Dummy)
- **역할:** 가장 단순한 형태. 객체가 필요하지만 **실제로 사용되지는 않을 때** 사용. 주로 파라미터 채우기 용도로 쓰임
- **예시:**
    ```java
    // 회원 가입 테스트를 하는데, '이메일 발송 서비스' 객체가 필요함.
    // 하지만 이 테스트에서는 이메일을 실제로 보내는지 확인할 필요가 없음.
    EmailService dummyEmailService = new DummyEmailService(); 
    UserService userService = new UserService(dummyEmailService);
    ```

#### 2. 스텁 (Stub)
- **역할:** 더미보다 한 단계 발전한 형태. **미리 준비된 답변(상태)을 반환**하는 객체. 호출되면 약속된 데이터만 돌려주고, 그 외의 복잡한 로직은 없음
- **예시:**
    ```java
    // "ID가 1인 사용자를 조회하면 항상 'Alice'라는 객체를 반환해라"라고 설정
    when(userRepository.findById(1L)).thenReturn(new User("Alice"));
    
    // 실제 DB 조회 없이 테스트 진행 가능
    User user = userService.getUser(1L);
    assertEquals("Alice", user.getName());
    ```

#### 3. 페이크 (Fake)
- **역할:** **실제 동작하는 구현체**를 가지지만, 프로덕션(운영) 환경에는 적합하지 않은 형태. 로직이 살아있어 실제 객체처럼 동작
- **예시:**
    - 실제 운영 환경: Oracle, MySQL 같은 대형 DB 사용
    - 테스트 환경: **인메모리 DB (H2)** 또는 **HashMap**을 사용하여 DB 역할을 대신하는 클래스 구현
    ```java
    // 실제 DB 대신 HashMap에 데이터를 저장하고 불러오는 FakeRepository 사용
    UserRepository fakeRepository = new FakeMemoryUserRepository();
    ```

#### 4. 스파이 (Spy)
- **역할:** 스텁의 역할을 하면서, 추가적으로 **자신이 어떻게 호출되었는지 기록**하는 객체. 몇 번 호출되었는지, 어떤 파라미터로 호출되었는지 등을 감시
- **예시:**
    ```java
    // 이메일 발송 메서드가 실제로 호출되었는지 확인하고 싶음
    emailService.send("welcome@test.com");
    
    // "send 메서드가 1번 호출되었는가?" 검증
    verify(emailService, times(1)).send("welcome@test.com");
    ```

#### 5. 목 (Mock)
- **역할:** **행위(Behavior)를 검증**하기 위해 사용되는 객체. 스텁과 비슷해 보이지만, "어떤 값을 리턴하느냐(상태)"보다 "어떤 메서드가 호출되었느냐(행위)"에 초점을 맞춤
- **예시:**
    ```java
    // "주문이 완료되면 결제 서비스의 pay() 메서드가 반드시 호출되어야 한다"는 행위를 정의
    OrderService orderService = new OrderService(mockPaymentService);
    orderService.completeOrder(order);
    
    // pay() 메서드가 호출되었는지 검증 (호출 안 됐으면 테스트 실패)
    verify(mockPaymentService).pay(any());
    ```

| 종류 | 목적 | 실제 동작 여부 | 검증 대상 |
| :--- | :--- | :--- | :--- |
| **Dummy** | 인자 채우기 | X | 없음 |
| **Stub** | 미리 준비된 값 반환 | X | 상태 (반환값) |
| **Fake** | 가벼운 로직 구현 | O (단순화됨) | 기능 동작 |
| **Spy** | 호출 내역 기록 | O (원본 감쌈) | 행위 (호출 여부) |
| **Mock** | 행위 검증 | X | 행위 (호출 여부) |
