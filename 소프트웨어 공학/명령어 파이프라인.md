# 명령어 파이프라인 (Instruction Pipelining)

CPU의 성능을 높이기 위해 **여러 명령어의 실행 단계를 중첩(Overlap)시켜 동시에 처리하는 기술**

---

## 1. 개념 및 동작 원리

### 기본 개념
전통적인 CPU는 하나의 명령어가 완전히 끝난 후에 다음 명령어를 시작했음. 하지만 파이프라인을 적용하면, 하나의 명령어가 실행되는 동안 **놀고 있는 다른 하드웨어 자원을 활용하여 다음 명령어를 미리 시작**할 수 있습니다.

### 명령어 처리 단계 (4~5단계 예시)
일반적으로 명령어 처리는 다음과 같은 단계로 나뉨
1.  **Fetch (IF)**: 메모리에서 명령어를 가져옴
2.  **Decode (ID)**: 명령어를 해석함
3.  **Execute (EX)**: 연산을 수행함
4.  **Memory Access (MEM)**: 메모리에 접근 (필요시)
5.  **Write Back (WB)**: 결과를 레지스터에 저장함

*   **파이프라인 적용 전**: 1번 명령어가 5단계(WB)까지 모두 끝나야 2번 명령어 시작
*   **파이프라인 적용 후**: 1번 명령어가 Decode 단계로 넘어가면, Fetch 유닛이 비므로 즉시 2번 명령어 Fetch 시작

## 2. 파이프라인 위험 (Pipeline Hazards) 및 해결책

파이프라인이 이상적으로 동작하지 못하게 방해하는 요소를 **해저드(Hazard)** 라고 함

### 1) 데이터 위험 (Data Hazard)
앞선 명령어의 연산 결과가 아직 나오지 않았는데, 뒤따르는 명령어가 그 데이터를 필요로 할 때 발생함

*   **상황**:
    ```assembly
    ADD R1, R2, R3  ; R1 = R2 + R3 (연산 중)
    SUB R4, R1, R5  ; R4 = R1 - R5 (R1이 아직 저장되지 않음)
    ```
*   **해결책**:
    *   **전방 전달 (Data Forwarding)**: 연산 결과가 레지스터에 저장되기 전이라도, ALU(연산 장치)에서 나온 결과를 바로 다음 명령어의 입력으로 우회(Bypass)하여 전달하는 기술
    *   **지연 (Stall)**: 데이터가 준비될 때까지 파이프라인을 잠시 멈춤 (성능 저하)

### 2) 제어 위험 (Control Hazard)
분기문(`if`, `goto`, 함수 호출 등)으로 인해 **다음에 실행할 명령어가 무엇인지 확신할 수 없을 때** 발생함

*   **상황**: 조건문(`if`)의 결과가 `True`인지 `False`인지 알기 전에, CPU는 미리 다음 명령어를 Fetch 해옴. 만약 예측이 틀렸다면 미리 가져온 명령어들을 모두 버려야 함
*   **해결책**:
    *   **분기 예측 (Branch Prediction)**: 과거의 실행 패턴을 기반으로 분기 결과를 미리 예측하여 실행함 (현대 CPU의 핵심 기술)
    *   **지연 분기 (Delayed Branch)**: 분기 명령어 뒤에 분기 결과와 상관없는 유용한 명령어를 배치하여 파이프라인을 채움

### 3) 구조적 위험 (Structural Hazard)
서로 다른 단계에 있는 명령어들이 **동시에 같은 하드웨어 자원을 사용하려 할 때** 충돌이 발생함

*   **상황**: Fetch 단계에서 메모리를 읽으려는데, Memory Access 단계에서도 데이터를 쓰기 위해 메모리에 접근하려고 할 때
*   **해결책**:
    *   **하버드 아키텍처 (Harvard Architecture)**: 명령어 메모리와 데이터 메모리를 물리적으로 분리하여 동시 접근을 가능하게 함

## 3. 개발자가 알아야 할 실무 포인트 (분기 예측 최적화)

현대 CPU의 파이프라인 깊이는 매우 깊기 때문에(Deep Pipeline), 분기 예측 실패(Branch Misprediction) 비용이 매우 큼

### 정렬된 데이터와 분기 예측
```java
// 정렬되지 않은 배열에서 조건문 실행
// 분기 예측이 자주 빗나감 -> 파이프라인 플러시(Flush) 빈번 -> 성능 저하
if (data[i] > 128) sum += data[i];

// 정렬된 배열
// T T T T T F F F F F 패턴 -> 분기 예측 성공률 매우 높음 -> 성능 향상
Arrays.sort(data);
if (data[i] > 128) sum += data[i];
```
*   실제로 대량의 데이터를 처리할 때, 데이터가 정렬되어 있다면 CPU의 분기 예측기가 패턴을 쉽게 학습하여 파이프라인 효율이 극대화됨 (성능 차이가 수 배 이상 날 수 있음)

### 요약
> **파이프라인은 CPU 성능의 핵심이지만, 데이터 의존성이나 분기문으로 인해 효율이 떨어질 수 있음.**
> 하드웨어는 Forwarding, Branch Prediction 등으로 이를 극복하며, 개발자는 분기 예측이 잘 동작하도록 코드를 작성(예: 데이터 정렬, 불필요한 조건문 제거)하여 성능을 높일 수 있음
