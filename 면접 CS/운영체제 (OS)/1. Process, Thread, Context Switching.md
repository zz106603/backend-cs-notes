## Process / Thread / Context Switching

### 운영체제(OS) 필요 이유

> 운영체제는 하드웨어와 프로그램 사이를 관리함
>
- 구조
    - `Application` → `Operating System` → `CPU / Memory / Disk / Network`
- Linux 같은 OS가 하는 일
    - CPU 스케줄링
    - 메모리 관리
    - 프로세스 관리
    - 파일 관리
    - 네트워크 관리
- 즉 OS가 없으면 프로그램이 CPU를 직접 제어해야 함

---

### Process

> **실행 중인 프로그램(instance)**
>
- ex) 설치된 프로그램
    - Chrome
    - Intellij
    - Java Application
    - 이건 그냥 파일
- 실행하면 Process가 됨
    - `java -jar app.jar` 실행 후 Process 생성

#### **Process는 독립 실행 환경**

- Memory
- File Descriptor
- Resource
- PID
- 자체적으로 가짐

#### Process Meomory

- 대표적
    - Code
    - Data
    - Heap
    - Stack
- 이 메모리는 다른 Process와 기본적으로 분리됨
    - **안정성 때문에 중요함**
    - ex) Chrome 탭 하나 죽어도 전체 OS가 죽지 않는 이유
- A 메모리를 B가 직접 건들지 못 함

---

### Thread

> **Process 내부의 실행 흐름(unit of excution)**
>
- Process 안에 최소 1개 thread 존재
- 필요 이유
    - **동시 작업**
    - ex) 웹 서버에서 동시에 요청 A, B, C 처리

---

### Process vs Thread

| 항목 | Process | Thread |
| --- | --- | --- |
| 메모리 | 독립 | 공유 |
| 생성 비용 | 큼 | 작음 |
| 통신 비용 | 큼 | 작음 |
| 안정성 | 높음 | 낮음 |

---

### Thread 공유

- 같은 Process 내 Thread는 공유
    - Heap
    - Code
    - Data
- 하지만 각 Thread는 자기만의 보유가 있음
    - Stack
    - Register

---

### Thread 가벼움

- Process 생성은 무거움
    - 새로운 **주소 공간, 메모리, Resource** 생성 필요
- Thread는 공유가 가능하기 때문에 가벼움

---

### Context Switching

- CPU 코어 수는 제한적
- ex) CPU 4코어, 실행 중 Thread 100개
    - 동시에 돌아가는 것처럼 보이는 이유가 Context Switching

#### Context

> Thread 실행 상태
>
- Program Counter
- Register
- Stack Pointer

#### Switching

- `Thread A 실행 → 멈춤 → Thread B 실행`
- 이 작업을 매우 빠르게 반복

#### 비용

- Switch 시 저장/복구 필요
- ex) Thread A 상태 저장
    - `register, stack pointer, pc`
    - Thread B 상태 로드
    - CPU 비용 발생

---

### Thread 개수

- Thread가 너무 많으면 문제가 발생
    - 메모리 사용 증가
    - Context Switching 폭증
    - CPU 낭비
- 그래서 Thread Pool 사용

#### Spring 서버 예시

- 요청마다
    - Tomcat worker thread
    - Service 호출
    - DB IO
    - MQ publish
- 전부 Thread 기반
- 즉 Thread 개수 튜닝이 성능과 연결됨
    - `server.tomcat.max-threads`

### 정리

#### Process와 Thread 차이?

- Process는 실행 중인 프로그램으로 **독립적인 메모리 공간과 시스템 자원**을 가짐
    - 따라서 안정성이 높지만 생성 비용이 큼
- Thread는 **Process 내부에서 실행되는 작업 단위**이며 같은 Process 내 Thread끼리는 Code, Heap, Data 영역을 공유함
    - 생성 비용이 작고 통신이 빠르지만 동기화 문제가 발생할 수 있음

#### Thread가 Process보다 가벼운 이유?

- Thread는 새로운 주소 공간을 생성하지 않고 **기존 Process의 메모리와 자원을 공유**하기 때문임
- Process보다 생성 비용과 전환 비용이 상대적으로 낮음

#### Context Switching?

- CPU가 현재 실행 중인 Process 또는 Thread의 상태를 저장하고 다른 Process 또는 Thread의 상태를 복원하여 실행 대상을 전환하는 과정
- CPU 코어 수보다 많은 작업을 번갈아 처리할 수 있지만, 상태 저장과 복원 비용 때문에 과도하면 성능 저하가 발생
