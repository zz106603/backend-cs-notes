## Memory (Stack / Heap / JVM)

### 프로그램 실행 시 메모리 구조

- 프로그램이 실행되면 OS는 프로세스에 메모리를 할당함
- 대표 구조

    ```java
    Process Memory
    ┌─────────────────────┐
    │ Code                │
    ├─────────────────────┤
    │ Data                │
    ├─────────────────────┤
    │ Heap    ↑           │
    │                     │
    │                     │
    │         ↓  Stack    │
    └─────────────────────┘
    ```

    - Code
    - Data
    - Heap
    - Stack

---

### Code 영역

> **실행 코드 저장**
>

```java
public int add(int a, int b){
	return a + b;
}
```

- 컴파일된 기계어 코드 저장
- 특징
    - 읽기 중심
    - 실행 명령 보관

---

### Data 영역

> **전역 / Static 데이터**
>

```java
static int count = 0;
```

- 특징
    - 프로그램 전체 생존

---

### Stack 영역

> **함수 호출 정보 저장**
>
- 지역 변수
- 매개 변수
- return address
- stack frame

```java
public void a(){
	int x = 1;
	b();
}

public void b(){
	int y = 2;
}
```

- a 호출

    ```java
    [a frame]
    x = 1
    ```

- b 호출

    ```java
    [b frame]
    y = 2
    -----------
    [a frame]
    x = 1
    ```

    - LIFO 구조
- b 종료

    ```java
    [a frame]
    x = 1
    ```

- 특징
    - 빠름
    - 자동 할당 / 해제
    - Thread별 독립

---

### Heap

> **동적 메모리 저장 영역**
>

```java
User user = new User("yun");
```

- 생성

    ```java
    Stack: reference  -> user
    Heap: User Object -> name = "yun"
    ```

- 구조

    ```java
    Stack
    user -> Heap(User 객체)
    ```

    - 변수 자체와 객체가 같은 곳 아님
- 필요 이유
    - 객체 크기를 컴파일 시 알 수 없음

    ```java
    List<User>
    Map<String, Object>
    ```

    - 런타임 동적 생성
    - Stack으로 관리 어려움

---

### Stack vs Heap

| 항목 | Stack | Heap |
| --- | --- | --- |
| 저장 | 함수 호출 | 객체 |
| 관리 | 자동 | GC/수동 |
| 속도 | 빠름 | 상대적 느림 |
| 크기 | 작음 | 큼 |

---

### Stack Overflow

> Stack frame이 너무 많이 쌓일 때 발생
>
- 대표적으로 무한 재귀

    ```java
     void recur() {
    	 recur();
     }
    ```

    - frame이 계속 증가하면서 `StackOverflowError` 발생

---

### Out Of Memory (OOM)

> Heap 부족
>

```java
while(true){
	list.add(new User());
}
```

- 객체 계속 생성
- Heap에 계속 쌓이는데 GC가 회수하지 못하면 `OutOfMemoryError` 발생

---

### Garbage Collection

> Computer Science에서 memory leak 방지 위해 등장
>

#### GC 대상

- 더 이상 참조되지 않는 객체

    ```java
    User user = new User();
    user = null;
    ```

    - Heap Object 참조가 없기 때문에 GC 대상이 됨

---

### Reachability

> 객체가 reachable이면 살아 있음
>
- ex) `GC Root` → `object A` → `object B`
    - 참조 경로가 있으면 회수하지 않음
    - 참조가 끊기면 GC 회수

---

### JVM Memory

> Java는 OS memory 위에 JVM memory 구조가 추가됨
>
- JVM
    - Heap
    - Stack (per thread)
    - Method Area
        - class metadata
        - static
        - constant pool

### 정리

#### Stack과 Heap의 차이?

- Stack은 함수 호출 시 생성되는 stack frame과 지역 변수, 매개 변수 등을 저장하는 메모리 영역
    - Thread마다 독립적으로 존재하며 LIFO 방식으로 관리됨
- Heap은 런타임에 동적으로 생성되는 객체가 저장되는 영역
    - Java 객체 대부분이 Heap에 생성되며 Garbage Collector가 관리

#### StackOverflow는 언제 발생?

- 함수 호출이 과도하게 중첩되어 Stack frame이 계속 쌓이고 Stack 메모리 한도를 초과할 때 발생
- 대표적으로 종료 조건 없는 재귀 호출에서 자주 발생

#### GC가 필요한 이유?

- Java는 객체를 Heap에 동적으로 생성하므로 사용이 끝난 객체를 회수하지 않으면 메모리 누수가 발생
- Garbage Collector는 더 이상 참조되지 않는 객체를 자동으로 회수해 Heap 공간을 확보함
