## DNS / Proxy / Load Balancer / CORS

### DNS (Domain Name System)

- ex) google.com → 142.x.x.x
- 도메인을 IP로 변환
- 실무에서는 DNS가 단순 lookup 이상
    - api.example.com
    - admin.example.com
    - cdn.example.com
    - 모두 다른 서버로 보낼 수 있음
- DNS가 트래픽 분산의 첫 단계가 되기도 함

---

### Proxy

> 대리 서버
>
- `Client → Proxy → Server`
    - 클라이언트와 서버 사이에서 대신 통신

#### Forward Proxy

- 클라이언트 대신 외부 요청
- ex) 회사 네트워크
    - `Employee PC → Proxy → Internet`
    - 캐싱, 우회, 접근 제어

#### Reverse Proxy

- `Client → Reverse Proxy → Backend`
- 클라이언트는 backend 직접 모름
- 필요 이유
    - **서버 숨김 (실제 backend IP 숨김)**
    - **SSL 종료 (HTTPS 복호화 처리)**
    - **로드밸런싱 (여러 서버 분산)**
- 대표
    - Nginx
    - HAProxy

---

### Load Balancer

> 트래픽 분산 장치
>
- ex) 서버 1대에 요청/응답이 많을 경우 여러 서버를 추가
    - Load Balancer가 분배
- 구조
    - `Client → Load Balancer → A or B or C`
- 필요 이유
    - **Scale-out (서버 추가 가능)**
    - **High Availability (서버 하나 죽어도 서비스 지속)**
    - **장애 격리 (죽은 서버 제외)**

#### Health Check

- LB가 주기적으로 검사
- `GET /health` → 응답 실패 → `Server A 제거`

---

### Load Balancing Algorithm

#### Round Robin

- 순서대로 A → B → C
- 단순함

#### Least Connections

- 연결 적은 서버 우선

---

### L4 vs L7

#### L4 Load Balancer

- 전송 계층 (Transport Layer)
- `IP`, `PORT` 기준으로 빠름

#### L7 Load Balancer

- 애플리케이션 계층 (Application Layer)
- HTTP 내용까지 봄
- ex)
    - API 서버 → `/api/*`
    - 이미지 서버 → `/images/*`
- 대표적으로 **Amazon Web Service ALB = L7**

### CORS

- ex) 연결 요청
    - 프론트 → `https://frontend.com`
    - 백엔드 → `https://api.com`
    - 브라우저 요청 → `fetch("htts://api.com")`
    - 브라우저가 막을 수 있음 → **Same-Origin Policy 때문임**
- 필요 이유
    - **브라우저 보안**
    - 악성 사이트가 백엔드 API 호출하는 위험 제한
- 해결 방법
    - 서버가 허용 선언
    - Response header
        - `Access-Control-Allow-Origin: https://frontend.com`

---

### Origin

> Origin 구성 = Protocol + Host + Port
>
- ex) `https://example.com:443`
    - 셋 중 하나라도 다르면 **cross-origin**

---

### Preflight Request

- 복잡한 요청은 먼저 검사
- 브라우저
    - `OPTIONS /api`
- 서버
    - `Allowed Methods: GET POST PUT`
    - 허용 시 본 요청

---

### 정리

#### Reverse Proxy 사용 이유?

- 클라이언트와 백엔드 서버 사이에서 요청을 대신 받아 전달하는 서버
- 서버 IP를 숨길 수 있고, SSL 종료, 캐싱, 로드밸런싱 등의 기능을 수행
- 운영 효율성과 보안이 향상됨

#### L4와 L7의 차이?

- L4는 Transport Layer에서 IP와 Port 기준으로 트랙픽을 분산
- L7은 HTTP 헤더나 URL 경로 같은 Application 레벨 정보를 보고 라우팅

#### CORS는 왜 발생?

- 브라우저의 Same-Origin Policy 때문에 발생
- 서로 다른 Origin 간 요청은 기본적으로 제한
- 서버가 Access-Control-Allow-Origin 헤더를 통해 명시적으로 허용해야 브라우저가 요청을 허용
